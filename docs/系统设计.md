# 系统设计

## Runtime 边界

本仓库实现基础 Agent Runtime Loop，但不实现具体 LLM Provider。使用者通过 `LLMClient` 注入真实模型调用；Runtime 负责 Context 构造、工具调用、预算控制、Run 状态和事件持久化。

Runtime 可使用 `RuntimeConfig` 配置执行预算：默认最多 12 轮 Loop、8 次工具调用、120 秒总耗时，单次工具调用超时 20 秒。对应环境变量配置字段为 `runtime_max_loops`、`runtime_max_tool_calls`、`runtime_max_duration_seconds` 和 `runtime_tool_timeout_seconds`。这些配置只提供边界，不实现 Loop 决策。

## 状态恢复

每个 Run 通过 Event 和 Checkpoint 持久化。`paused` Run 可以恢复；`completed` 和 `failed` Run 为终态，不能在原 Run 上重复执行。恢复时读取 checkpoint 和事件序列，Context 摘要使用已压缩消息计数避免重复累积。

## 工具安全

calculator 使用 AST 白名单；read_docs 使用固定文档根目录和路径穿越校验；search 通过 Provider 抽象接入外部服务，默认使用 Mock Provider。

## Context

Context 按系统指令、Session 摘要、相关记忆、未解决问题、最近消息组织。超限时保留最近消息并生成确定性摘要，不依赖 LLM。

## 会话历史边界

每条用户消息创建一个新的 Run。新 Run 只从同一 Session 中读取状态为 `completed` 的历史 Run，并按持久化顺序继承用户消息和最终 assistant 回答；失败、暂停 Run 以及工具调用中间消息不进入新 Run 的跨轮历史。不同 Session 不共享历史。

恢复已有的 `paused` Run 时，只回放该 Run 自身完整事件序列，并使用 checkpoint 中的 `compacted_message_count` 保持摘要计数一致；不会再次拼接跨 Run 历史，因此不会重复用户消息。`completed` 和 `failed` Run 不能恢复。

Context 的最近消息按完整工具调用组裁剪：assistant 的工具调用消息必须与对应 tool 结果一起保留或一起丢弃，不产生孤立的 tool 消息。

## 串行工具调用限制

Runtime 当前只支持每个 LLM 回合执行一个工具调用。OpenAI-compatible Provider 请求显式设置 `parallel_tool_calls=false`；如果 Provider 仍返回多个工具调用，客户端返回协议错误并结束当前 Run，不静默丢弃后续调用。

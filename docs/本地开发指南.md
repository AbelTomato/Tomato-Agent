# 本地开发指南

Tomato Agent 以 Tauri 桌面应用形式开发和交付。仓库 `backend` 下的 Python 包是内部助手引擎和测试目标，不是单独维护的 Web 服务。旧 Web/WSL 使用方式只保留在带日期的历史验收记录中。

## 桌面界面与宿主

首次使用时安装 Tauri CLI 和 UI 依赖：

```powershell
cd desktop
pnpm install
cd ui
pnpm install
cd ..
pnpm dev
```

默认开发入口会启动 Tauri 窗口。UI 不作为受支持的浏览器产品单独启动。Rust 测试命令：

```bash
cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked
```

从 WSL 检出目录构建 Windows Release/NSIS 安装包时，在仓库根目录运行 `desktop/scripts/windows.ps1 -Action build-release`。脚本会构建 UI、冻结 Windows Python 引擎，再调用 Windows MSVC/Tauri 工具链。该构建流程不意味着安装后的应用依赖 WSL。

## Python 引擎开发

桌面应用通过私有启动通道提供引擎配置和 API 凭据。单独开发 Python 子系统或运行回归时，保留现有本地 `backend` 环境和数据位置：

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest tests
```

安装版引擎使用桌面应用明确提供的数据和资源目录。本地 `.env`、`config.local.toml`、SQLite 数据和测试产物均属于开发机状态，不要打入安装包或提交版本库。

## 验证范围

- UI 行为测试：`cd desktop/ui && node --test tests/*.test.mjs`
- UI 生产构建：`cd desktop/ui && pnpm build`
- Rust 桌面测试：`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked`
- Python 引擎回归：`backend/.venv/bin/python -m pytest backend/tests`

常规测试使用 fake Provider。Docker、OpenShell 和真实 Provider 检查是独立的显式 opt-in 流程。健康检查成功或本地可控 Provider 通过，都不代表第三方服务商兼容性已经验收。

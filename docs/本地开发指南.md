# 本地开发指南

本文覆盖本地开发环境和跨平台启动。快速入口见 [README](../README.md)。下文的项目根目录指你克隆仓库的位置；每组平台命令是独立方案，选择一组执行即可。

## 环境与配置

- Python ≥ 3.11。
- 与当前 Vite 兼容的 Node.js；pnpm 版本为 `10.34.5`，见 [package.json](../frontend/package.json)。
- 在后端目录复制 [环境变量模板](../backend/.env.example) 为 `.env`，配置 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`。后端从启动工作目录读取 `.env`，因此应在后端目录启动。
- Embedding 配置为空时只启用关键词检索。向量和混合检索需要单独配置 Embedding Provider，并完成语料导入与索引，见[知识库使用说明](知识库使用说明.md)。
- `.env` 中的凭据仅保存在本地，不提交到仓库。

## 启动后端

每组命令均从项目根目录开始。复制模板仅在首次配置时执行，已有 `.env` 时请保留原配置。

### Linux / macOS

```bash
cd backend
cp .env.example .env
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

编辑 `.env` 后，在同一终端执行：

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### Windows PowerShell

```powershell
cd backend
Copy-Item .env.example .env
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
```

编辑 `.env` 后，在同一终端执行：

```powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

若禁止执行激活脚本，可在后端目录直接使用虚拟环境解释器：

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### Windows CMD

```bat
cd backend
copy .env.example .env
py -3.11 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -e .
```

编辑 `.env` 后，在同一终端执行：

```bat
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

## 启动前端与检查连接

在项目根目录打开另一个终端：

```bash
cd frontend
pnpm install
pnpm dev
```

访问 <http://localhost:5173>。API 文档为 <http://127.0.0.1:8000/docs>，健康检查为 <http://127.0.0.1:8000/health>；健康检查成功仅表示服务可响应，不代表模型或 Sandbox 已可用。

前端默认连接 `http://127.0.0.1:8000`。需要更换后端地址时，在前端目录的 `.env.local` 中设置 `VITE_API_BASE_URL` 并重启 Vite。后端默认允许 `localhost:5173` 和 `127.0.0.1:5173` 两个前端来源；更换端口或来源时需相应调整后端 CORS 配置。

## 常见环境问题

### Ubuntu / Debian 缺少 venv

根据系统权限安装组件，再重新创建虚拟环境：

```bash
sudo apt update
sudo apt install python3-venv python3-full
```

### 未找到 pnpm

如果当前 Node.js 环境提供 Corepack，可启用并安装项目指定版本：

```bash
corepack enable
corepack prepare pnpm@10.34.5 --activate
```

若没有 Corepack，请按 pnpm 官方安装说明准备 `10.34.5` 版本。

### 模型调用或代码任务不可用

核对后端 `.env` 的 Provider 地址、模型名称和凭据；不要将密钥写入诊断输出。普通服务启动不等于代码任务隔离后端已配置，Docker/OpenShell 配置和真实验收见[受控代码任务说明](受控代码任务说明.md)。

## 开发验证入口

在后端虚拟环境中安装声明的测试依赖：`python -m pip install -e '.[test]'`。按修改范围选择相关测试，不必每次运行完整项目测试。

- 代码任务契约与闭环命令见[受控代码任务说明](受控代码任务说明.md)。真实验收会创建 Sandbox 并产生模型费用。
- 写作测试在后端目录运行：`python -m pytest tests/test_writing*.py -q`（Linux / macOS shell 展开文件名）；流程及验收限制见[技术写作 Agent 说明](技术写作Agent说明.md)。
- RAG 评测命令见[知识库使用说明](知识库使用说明.md)和 [Benchmark 使用说明](评测/Benchmark使用说明.md)。实验使用独立快照，数据库与报告分别保存在 `backend/data/rag/databases/` 和 `backend/data/rag/reports/`，不得写入业务数据库。

# 文档编写规约

本规约适用于 `docs/` 下的 Markdown 文档。新增或修改文档时遵循以下约定：

- 使用 UTF-8 Markdown；标题层级从一个 `#` 开始递增，不跳级。文件名使用简洁、可检索的主题名；新计划和调研使用 `YYYY-MM-DD-主题.md`，开发日志使用 `YYYY-MM-DD.md`。已有文件名作为历史引用保留，除非迁移本身要求更新路径。
- 文档开头说明用途和适用范围。对历史方案、计划状态或验收结论标注日期与状态，区分已实现、已验证、未完成和建议，不把历史结论写成当前事实。
- 以仓库根目录为路径基准记录文件位置，不写作者机器的绝对路径、用户名、临时目录或个人构建产物路径。需要引用仓库文件时使用有效的相对 Markdown 链接或反引号路径。
- 更新或移动文档时同步修复仓内引用，并检查目标文件存在。优先维护单一权威说明，其他文档链接到它，避免复制相互冲突的操作步骤。
- 操作指南写前置条件、步骤、结果和限制；架构/决策文档区分事实、决策与待选方案；验收记录写清环境、命令/范围、结果和未覆盖项。
- 实施计划写目标、范围、依赖、分阶段任务、验收条件和状态；已完成项保留可核实结果。开发日志按日期记录完成内容、问题、解决方式、验证结果和限制，不记录密钥或可复用凭据。
- 发布说明以用户可见变更和已知限制为主。评测和调研记录数据集/来源、方法、结果及结论适用边界。
- 修改后运行 `git diff --check`；文档迁移还需检查旧路径引用和 Markdown 本地链接。

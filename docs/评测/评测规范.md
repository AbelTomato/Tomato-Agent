# 个人博客 RAG 评测规范

## 目标与边界

本规范定义个人博客知识库的离线检索与人工回答评测约定。固定测试语料仅验证导入、检索和评测工程行为，不得用其成绩代表真实博客上的效果或模型语义质量。

真实博客接入后，人工标注首批 20–30 个问题，存放于 `/home/abeltomato/workspace/projects/Tomato-Agent/backend/evals/blog_questions.jsonl`。每行一个 JSON 对象；问题按主题分组切分为开发集和保留测试集，避免相似问题跨集合泄漏。真实语料不足时如实记录，不通过自动生成相似问题补足数量。

## 语料清单

导入清单是 UTF-8 JSON 数组。每项必须包含以下字段：

| 字段 | 类型 | 约束 |
|---|---|---|
| `path` | string | 知识库根目录内的相对 Markdown 路径；不得重复、不得目录穿越，且目标文件必须存在。 |
| `title` | string | 非空文章标题。 |
| `url` | string 或 null | 外部原文地址；存在时仅允许带主机名的 `http` 或 `https` URL。 |

固定离线语料位于 `/home/abeltomato/workspace/projects/Tomato-Agent/backend/tests/fixtures/knowledge/`，包括中文标题、英文 API 标识符、代码围栏、跨文章同名章节和一段不可信伪指令。该伪指令只能作为检索内容，不能改变系统提示词、工具白名单或服务端权限。

## 问题数据格式

Benchmark 对单一 split 运行时只解析 JSONL 中该 split 的记录；不解析或输出保留 `test` 记录内容。dev runner 的数据集指纹基于规范化后的所选题目计算。题集分组完整性由经人工复核的正式 manifest/题集维护流程确认；需要跨 split 泄漏检查时，应在不展示保留题内容的独立校验流程中完成。

每个 JSONL 记录必须包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定且唯一的问题标识。 |
| `query` | string | 用户原始问题。 |
| `category` | string | 至少覆盖术语、改写、跨文章、无答案四类。 |
| `split` | string | `dev` 或 `test`；按主题分组划分。 |
| `answerable` | boolean | 语料是否应能支持回答。 |
| `relevant_spans` | array | 证据列表；无答案问题使用空数组。 |
| `reference_answer` | string | 人工参考答案；无答案问题说明应拒答或材料不足。 |

每个 `relevant_spans` 元素包含 `document_id`、`document_version`、`start_line`、`end_line`。行号为从 1 开始的闭区间；`start_line` 和 `end_line` 必须为正整数，且 `start_line <= end_line` 并落在对应文档版本的总行数以内。证据不引用具体 `chunk_id`，避免分块参数变化使标注失效。

```json
{"id":"redis-setex-001","query":"SETEX 如何同时写值和过期时间？","category":"术语","split":"dev","answerable":true,"relevant_spans":[{"document_id":"redis-cache","document_version":"<内容哈希>","start_line":5,"end_line":11}],"reference_answer":"SETEX 在写入字符串值时同时设置过期时间。"}
```

`<内容哈希>` 是占位说明，不是可提交的真实标注版本；真实数据必须填写导入后记录的文档版本。

## 指标与报告原则

检索 Benchmark 按相同文档版本及片段完整覆盖标注行范围计算 Evidence Recall@1/3/5、MRR@5 和 Hit@5。Recall 先逐题计算相关证据段命中比例，再对可回答题宏平均；相关证据命中 1/2 时该题 Recall 为 0.5，首个相关结果排名第 2 时 RR 为 0.5，无命中时 Hit 为 0。按类别汇总时同时记录有效样本数。

无答案样本不进入证据召回分母，分别统计无答案空结果率和非空检索率；这些是检索代理指标，不代表语义正确拒答或错误作答。超时、协议错误等执行失败单独计入执行错误率，不算空结果或拒答，也不进入质量指标分母；含失败题的运行不得判为 complete。零分母的指标输出 `null` 和样本数，不以 `0` 代替。报告必须同时记录语料哈希、问题数量与类别、检索模式和参数、模型与索引版本、检索延迟及人工答案评估。离线检索耗时、端到端耗时和模型费用不得混为一谈；未知 usage 或费用必须标记为未知。

在开发集上调节分块和 `top_k`；保留集仅用于最终报告。查看保留集后继续调参时，必须将其标记为不再独立。每份真实报告至少列出五个代表性失败样例、归因及下一步，不夸大固定语料或合成测试的结果。

## 离线 RAG Observe、隐私与指标口径

- Observe Trace 采用版本化契约 `rag-observe-trace/v1`，仅供显式启动的本地离线 `dev` 评测使用。完整 query、检索证据、`LLMClient.complete(messages, tools)` 实际接口输入及模型输出属于受控评测数据，只能保存到授权的项目内目录 `/home/abeltomato/workspace/projects/Tomato-Agent/backend/data/rag/reports/` 下独立 run 目录；不得写入一般应用日志、外部观察平台或在线请求 sink。当前在线服务默认不注入持久化 observer/sink。
- Trace run 必须包含题目逐题工件、事件 JSONL、汇总及 manifest。manifest 中的文件清单记录字节数与 SHA-256；事件具有连续序号和前序事件哈希，完整性校验失败或任一题执行失败时，run 必须为 `incomplete`，不得报告为成功完成。目录权限为 `0700`、文件为 `0600`，run ID 冲突时拒绝覆盖。
- 完整输入和答案工件默认自运行完成起保留至多 30 个自然日；到期由数据负责人按项目数据处理流程复核并清理，或书面批准延长。runner 不自动删除或延长保留期。若适用的合规/数据处理要求期限短于 30 日，必须采用更短期限。人工复核仅记录非敏感 reviewer ID，不将凭据、Token、Authorization Header 或完整环境变量写入工件。
- 观测写入/校验失败与问答执行状态分开记录；任何题执行失败均不算正确拒答。候选池命中不代表证据进入最终选择或实际模型上下文；最终上下文包含证据也不代表模型回答被证据语义支持。引用 ID 通过白名单校验仅说明引用映射有效，不证明引用支撑答案。
- `supported` 是机器 Judge/model 状态，不是人工语义结论。答案机器质量缺省为 `not_evaluated`；人工复核分别评估正确性（correctness）、完整性（completeness）、groundedness 和引用忠实度（citation fidelity），并报告各维度样本数及标签，不能用单一“通过”合并替代。
- 分开报告 candidate pool 与 final evidence 的证据 Recall/MRR/Hit、Answerability/Judge 状态、引用白名单结果、LLM 请求/尝试/失败/跳过计数、逐阶段耗时与端到端耗时。未调用模型时标明未调用；未知模型用量或费用保持未知，不从耗时推算成本。机器检索指标、模型 Judge、人工语义复核不得互相替代。

真实 Observe 复验只能使用经确认批准的隔离 `dev` 快照和题集，输出写入上述 reports 目录中新建且不可覆盖的 run 目录；执行前后核对数据集与快照 SHA-256，只读取 `dev` 行，不访问 `test` split 或业务数据库。外部 LLM 请求的调用范围和预算须在运行前单独确认。

Agent 工具评测除了检查最终回答，还必须检查当前 Run 的 Event/Checkpoint：

1. `search_knowledge` 结果只包含片段 ID、文档版本、来源和受长度限制的摘录；不接受文件路径。
2. `read_knowledge` 只能按仓储中的 `chunk_id` 读取，并在成功事件中记录已读片段 ID和文档版本。
3. 最终回答引用只能来自当前 Run 已成功读取的片段；仅搜索到但未读取的片段不能作为“已读证据”。
4. 未知 ID、参数校验错误、工具执行失败和超预算必须在工具事件或 Run 失败事件中可区分，不能伪造成功结果。
5. 固定测试至少覆盖“搜索→读取→回答”、未知 ID、工具失败、工具预算耗尽和结果长度限制；真实模型的工具选择质量另行人工评估。

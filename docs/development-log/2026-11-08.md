## 桌面 Provider 网络实现诊断（初次复测）

- **诊断结果**：当前桌面聊天 `reqwest` 配置使用 `default-features = false`，原先没有启用 TLS backend，也关闭了 reqwest 默认启用的 `system-proxy`。Windows Internet Settings 当前配置代理 `127.0.0.1:7890`，但聊天应用由 Explorer 启动且没有代理环境变量；旧 Web 版 Python `httpx` 使用环境代理。TLS 缺失与系统代理未接入均可导致快速网络错误，与 API Key 无效不等价。
- **超时对照**：桌面聊天请求为 120 秒总超时，连接测试原先只有 20 秒；历史 Web 版 `OpenAICompatibleClient` 默认 60 秒。连接测试现在与聊天对齐为 120 秒；都不自动重试。
- **代码修复**：`reqwest` 显式启用 `rustls-tls` 和 `system-proxy`，连接测试期限提升至 120 秒。chat-only Rust 锁定测试 9/9 通过，默认 Rust 测试 16/16 通过，差异检查通过。
- **Windows 实测边界**：初次绕过 WSL 前端构建时使用了通用 `frontend/dist`，导致安装包虽含 `desktop-chat` Rust feature，页面仍落回旧桌面链；该次未用于 Provider 请求。随后重新构建 chat-mode 前端，核对新安装首屏并完成真实 Provider 场景，详见下方最终验收记录。

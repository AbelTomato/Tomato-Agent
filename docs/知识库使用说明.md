# 知识库使用说明

## 支持范围

第一版导入器仅接受 UTF-8 编码的 `.md` 或 `.markdown` 文件。解析 ATX 标题（`#` 至 `######`）以及反引号或波浪线代码围栏；围栏内的 `#` 不会被识别为标题。YAML front matter 不参与元数据解析，文章标题和 URL 以显式清单为准。

普通内容以约 500 tokens 为目标、800 tokens 为上限按章节和段落分块；代码围栏独立保留。单个代码块超过 2,000 tokens 会使该文档导入失败，不会静默截断。每个片段保存标题路径和原文行号。

## 清单格式

清单为 UTF-8 JSON 数组，`path` 必须是根目录内的相对 Markdown 路径，`title` 非空，`url` 可为 `null` 或 `http/https` 地址：

```json
[
  {
    "path": "2026/example.md",
    "title": "示例文章",
    "url": "https://example.com/blog/example"
  }
]
```

重复路径、目录穿越、符号链接逃逸、无效 URL、缺失文件、非法编码和空文档会被拒绝或记录为失败。导入不会扫描根目录中未在清单列出的文件。

## 导入与同步

在 `/home/abeltomato/workspace/projects/Tomato-Agent/backend` 中执行：

```bash
.venv/bin/python -m app.knowledge.cli ingest \
  --manifest /absolute/path/manifest.json \
  --root /absolute/path/to/blog
```

相同内容再次导入会跳过，不产生重复片段；文章变更时仅在单个数据库事务中替换该文章的片段，并将 Embedding 索引标记为待更新。导入失败时旧版本保持不变。默认不会删除清单中消失的文章。

## Embedding 索引与查询闭环

导入和向量索引是两个显式阶段：`ingest` 只读取清单、解析 Markdown 和保存片段，不会因 Embedding 配置为空而访问外部服务；`index` 才会按批次调用配置的 OpenAI-compatible `/embeddings` Provider。索引记录保存 `model`、`dimensions`、文档版本和片段文本哈希，Provider 返回数量、维度或有限数值不符合要求时，该文档会记录 `index_status=failed` 和 `index_error`，并清理本次目标模型/维度的部分向量，不删除其他模型或维度的索引。

配置 Embedding（不要复用聊天模型配置）后，在后端目录执行：

```bash
export EMBEDDING_API_KEY='不写入代码或日志的密钥'
export EMBEDDING_BASE_URL='https://api.openai.com/v1'
export EMBEDDING_MODEL='text-embedding-3-small'
export EMBEDDING_DIMENSIONS='1536'

.venv/bin/python -m app.knowledge.cli ingest \
  --manifest /absolute/path/manifest.json \
  --root /absolute/path/to/blog
.venv/bin/python -m app.knowledge.cli \
  --database /absolute/path/to/knowledge.db \
  index \
  --embedding-model "$EMBEDDING_MODEL" \
  --embedding-dimensions "$EMBEDDING_DIMENSIONS" \
  --batch-size 32
```

`index` 可重复执行：同一文档、模型、维度、版本和片段文本哈希均匹配且状态为 `ready` 时跳过 Provider 调用；内容更新、索引失败或切换模型/维度时会重建对应配置。重建某个模型/维度不会删除同一文档的其他索引。缺少 `embedding_api_key` 时 CLI 返回非零状态并输出稳定的 `error:`，不会发起请求。

服务启动后可先查看当前查询能力：

```bash
curl http://127.0.0.1:8000/api/knowledge/capabilities
```

配置完整时返回的 `retrieval_modes` 包含 `keyword`、`vector`、`hybrid`；未配置 Embedding 时只提供 `keyword`。创建 Session 后，通过知识问答接口选择检索方式：

```bash
SESSION_ID=$(curl -s -X POST http://127.0.0.1:8000/api/sessions \
  -H 'Content-Type: application/json' -d '{}' | python -c 'import json,sys; print(json.load(sys.stdin)["session_id"])')
curl -s -X POST "http://127.0.0.1:8000/api/sessions/${SESSION_ID}/knowledge-runs" \
  -H 'Content-Type: application/json' \
  -d '{"message":"SETEX 如何设置过期时间？","retrieval_mode":"hybrid","limit":5}'
```

向量和混合检索使用服务端 `embedding_model` 与 `embedding_dimensions` 生成查询向量，并拒绝与已存索引不兼容的模型/维度；不会把关键词结果静默标记为向量或混合结果。返回的 `citations` 包含文档版本、标题路径、原文行号和片段正文，可通过 `GET /api/knowledge/documents/{document_id}` 查看已导入原文。

向量/混合模式默认使用 `knowledge_min_vector_similarity=0.5` 作为最低余弦相似度门槛，也可通过环境变量或评测 CLI 的 `--min-vector-similarity` 调整，合法范围为 `0` 到 `1`。`vector` 会过滤低于门槛的向量结果；`hybrid` 会先按原始向量相似度过滤，再执行 RRF，不能用 RRF 分数替代余弦相似度。若没有任何向量结果达到门槛，服务返回 `evidence_status=no_results`、空 `citations` 和空回答，不调用 LLM；关键词模式不使用该门槛。当前门槛依据 5 题真实博客 `dev` smoke 集的 top-1 分数初步设定，仍需更多带标签的开发集、硬负例和人工回答质量评估后校准。

## 当前确定性检索与 Embedding 协议基线

`KnowledgeRepository.search_chunks(query, limit=5)` 提供本地 SQLite 关键词检索，返回片段正文以及以下引用元数据：文档 ID、文档版本、相对路径、文章标题、公开 URL、标题路径和原文起止行号。

- 空白查询、非正数 `limit` 或无命中时返回空列表。
- 关键词基线使用字段加权 BM25：标题权重为 3、标题路径为 2、正文为 1；英文标识符保留完整形式并识别 `.`、`_`、`-` 分段，中文词组使用相邻双字 token。
- 中文词组要求全部相邻双字均在同一个片段的标题、标题路径或正文中出现，避免仅命中个别常见字词；结果按分数降序和路径、行号、片段 ID 稳定排序。
- `app.knowledge.embeddings.EmbeddingClient` 提供独立的 OpenAI-compatible `/embeddings` HTTP 协议适配器。配置使用 `embedding_api_key`、`embedding_base_url`、`embedding_model`、`embedding_dimensions`、`embedding_timeout_seconds`，不复用或假定聊天模型配置可用。
- `Embedding 响应会校验批量索引、数量、维度及有限数值；协议错误不会回显凭据或上游响应体。导入阶段不会调用该客户端，显式执行 `index` 时才会按批次请求外部服务。
- SQLite 的 `embeddings` 表用于保存分块向量及模型、维度、文档版本、文本哈希元数据；索引状态保存在 `documents.index_status/index_error`，包括 `pending`、`indexing`、`ready` 和 `failed`。旧数据库初始化时会补充缺失的 `index_error` 列。文档内容更新时旧向量在同一替换流程中清理。
- `KnowledgeRepository.search_vector_chunks(...)` 和 `search_hybrid_chunks(...)` 的底层接口接收查询向量；通过 `KnowledgeService` 查询时，若 Embedding 配置完整，服务会调用配置的 `EmbeddingClient` 自动生成查询向量，并校验查询模型/维度与已存索引兼容。Embedding 未配置时只提供关键词检索；向量/混合请求不会静默降级。混合检索先按可选最低原始余弦相似度过滤，再按 `chunk_id` 使用 RRF 去重合并。

查看同步候选删除项：


## 知识助手前端

在 `/home/abeltomato/workspace/projects/Tomato-Agent/frontend` 中执行：

```bash
pnpm install
pnpm dev
```

前端默认请求 `http://127.0.0.1:8000`；如需修改地址，设置 Vite 环境变量 `VITE_API_BASE_URL`。页面支持知识问答和基础聊天两种模式。知识问答可选择关键词、向量或混合检索，并通过 `GET /api/sessions/{session_id}/messages` 在刷新后恢复已完成消息。

Session ID 保存在浏览器 `localStorage`。后端返回 404 时会清除失效 ID，并提示用户新建会话；发送请求期间输入框、模式选择和发送按钮会禁用，避免重复提交。请求状态会区分恢复中、处理中、成功、失败和材料不足。

回答中的引用以纯文本渲染，展示标题、章节、摘录和原文行号。仅 `http`/`https` URL 会作为外部链接打开；无 URL 或不安全 URL 时只能通过后端文档 ID 调用来源接口查看已导入原文，不接受任意文件路径。基础聊天结果不会伪装成知识库来源。

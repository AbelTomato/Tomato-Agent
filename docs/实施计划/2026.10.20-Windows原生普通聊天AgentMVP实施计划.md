# Windows 原生普通聊天 Agent MVP 实施计划（计划日期：2026-10-20）

> 本计划基于已确认的普通聊天 MVP 需求。当前阶段只制定方案，不代表以下实现已经开始。

**目标：** 交付 Windows 安装后即可启动的 Tomato Agent 桌面应用，支持模型配置、多会话普通文本对话、流式回复和本地历史，不依赖 WSL、用户工作区或用户预装 Python。

**架构：** 沿用 Tauri 2 + React/Vite 外壳，但建立独立的普通聊天页面、命令/API、数据与运行时边界，不复用旧 WSL/工作区桌面链。先实现本机开发可运行的最小纵向闭环（配置、单会话发送、流式返回、SQLite 恢复），再根据闭环的真实部署需求选定并验证随包运行时；产品边界始终是不要求用户安装 Python 或 WSL。

**技术栈：** Tauri 2 / Rust、React + TypeScript + Vite、SQLite；复用仓库现有依赖和测试模式。OpenHands 仅提供 Agent 运行时与用户工作区解耦的参考，不照搬其 Electron/Python 架构。

**需求依据：** 本计划对应已确认的 Windows 普通聊天 MVP 草案；现有背景和迁移记录见 `docs/实施计划/2026.10.20-桌面项目多目录与普通聊天实施计划.md`、`docs/实施计划/2026.10.19-桌面执行环境按需连接实施计划.md`、`docs/archive/windows/Windows桌面连接与生命周期.md`。如实现时需改变以下产品边界，先更新本计划并重新确认。

## 全局约束

- 用户安装和启动 Windows 应用不要求 WSL、工作区、Python 或开发工具。
- MVP 仅提供模型设置、多个独立会话、普通文本多轮聊天、流式输出、停止生成、错误反馈和本地历史恢复。
- 不包含项目/目录管理、工作区、文件读取或写入、工具调用、终端、知识库、代码执行、自动化任务或 WSL 集成。
- 每个会话只持有自己的消息历史；模型请求不得注入项目、文件或工具上下文。
- API Key 使用 Windows Credential Manager 等系统凭据存储；不得写入 SQLite、明文配置、前端持久化、日志或诊断报告。
- 用户已明确授权将当前 10 个桌面相关未提交文件纳入本阶段代码提交；按本计划范围更新它们，不清理、不重置、不覆盖与任务无关的内容。新旧桌面运行入口继续隔离，旧链删除不属于本阶段。
- 旧桌面实现可作为历史材料只读检查，但新 MVP 不得依赖、调用、导入或复用旧 WSL 连接/生命周期、工作区、项目和统一任务流程；旧实现的成功/失败记录不得作为新 MVP 的验收证据或架构正确性证明。
- 每个新模块必须从独立入口显式装配；启动时不得隐式探测 WSL、读取旧环境偏好、连接旧服务、初始化旧 Agent/Knowledge 数据库或启动旧 Worker。
- 计划和开发日志按仓库约定写入 `docs/实施计划/` 与 `docs/development-log/`，不加入 Git。

## 范围与验收定义

### 必须支持

1. 首次启动显示可用配置表单：兼容 OpenAI Chat Completions 的 API Base URL、API Key、模型名；允许测试连接并安全保存/替换/删除凭据。端点与模型名称保存在应用本地设置，密钥只存系统凭据库。此协议选择为 MVP 默认实现；若用户目标 Provider 不能兼容该协议，需先更新需求。
2. 创建、列出、切换、重命名和删除会话。删除会话须有明确确认。新建会话立即本地落库；标题由用户命名，自动摘要不属于 MVP 必需功能。
3. 在当前会话发送纯文本，按时间顺序将 user/assistant 消息持久化，支持多轮上下文、流式展示、停止当前生成及刷新/重启后恢复历史。
4. 明确显示未配置、请求中、无网络/超时、认证错误、Provider 错误、空回复和用户取消状态；失败不得伪装成完整 assistant 答案。重试由用户显式触发，禁止对聊天 POST 自动重试。
5. 产出 Windows 安装包并在干净 Windows 环境安装、启动、配置模型、对话、重启恢复。Windows 普通用户无需预装 Python、WSL 或外部服务。

### 明确不做

- 现有 Web 主应用能力的整体重写或删除；旧 WSL/工作区桌面链路的代码清理。
- 云同步、账户系统、多设备同步、跨设备凭据迁移、附件/图片/语音、Markdown 编辑器增强、消息编辑/分支、搜索和自动会话摘要。
- 工具调用、RAG/知识库、文件/终端访问、代码生成后执行、后台 Agent/任务、项目或多目录语义。
- 通用 Provider 插件市场或每个 Provider 的专属 OAuth 流程。

### 发布验收门槛

- 干净 Windows 用户环境下安装器安装成功，首次启动无控制台窗口、Python/WSL 探测或开发环境提示。
- 未配置模型时不能发送请求，且能从设置完成配置与连通性检查。
- 至少一次真实模型验收覆盖流式回复、多轮上下文、停止、断网/错误显示及重启后历史恢复；真实 Provider 请求须显式 opt-in，记录 Provider/模型/端点主机和测试结果，不记录密钥或消息正文。
- 构建产物具备版本号、卸载能力和明确数据目录；升级不得意外删除会话数据库或凭据。
- 前端、Rust、后端及 Windows 安装验收分别记录；工程测试通过不得冒充 Windows 实机或真实 Provider 验收。

## 分阶段任务

### 阶段 0：隔离基线与新入口骨架

1. 实施前记录 Git 状态、10 个保护文件的改动边界和现有工作区；只读检查 Tauri 命令注册/启动生命周期、前端根路由、依赖清单和 Windows 打包配置。不得先验收旧应用或把旧验收结论当作新方案输入。
2. 新增独立 `DesktopChatApp` 页面入口、`desktop_chat` 原生命令/服务模块和独立开发路由或启动配置；在此阶段不连接模型、不启动旧服务。共享入口文件只做最小装配改动，若与保护文件既有改动冲突则停下处理。
3. 新入口启动时只显示空聊天壳和未配置状态。用定向测试断言它不调用旧 WSL bridge、不读取旧环境设置、不请求项目/工作区/任务 API、不启动 worker。
4. 验收本阶段交付物：开发模式可独立打开新空聊天界面；旧页面仍保持原状；保护文件改动未丢失。此处是新入口的工程测试，不是 Windows 产品验收。

### 阶段 1：最小纵向闭环

1. 测试先行定义最小配置（OpenAI Chat Completions 兼容 base URL、模型名；凭据由原生凭据适配器提供）、会话/消息 DTO 和 Provider 接口。会话 ID 使用 UUID；消息角色只允许 `user`/`assistant`；时间使用 UTC ISO-8601。
2. 新增桌面专用 SQLite 文件和最小 schema，实现会话创建、消息追加/读取、重启恢复。数据放在新的 Tomato Agent 应用数据子目录，绝不打开 `agent.db`、`knowledge.db` 或旧桌面数据库。
3. 提供 fake Provider 和一个最小聊天提交路径：保存 user 消息、发起流、展示 delta、成功后保存 assistant 回复；覆盖取消、失败与空响应，先不做会话管理全套和最终安装器。
4. 提供新的模型设置界面和 Tauri Credential Manager 适配器；密钥仅在提交模型请求时短暂经过进程内存，不返回给前端，不写 SQLite/配置/日志。测试缺少凭据、替换、删除和系统凭据库不可用。
5. 验收本阶段交付物：开发模式从新入口完成 fake Provider 的“配置状态—发送—流式显示—本地保存—重启恢复”闭环；自动化测试确认旧模块调用次数为零。此阶段不需要真实 Provider 或干净 Windows 安装验收。

### 阶段 2：完整会话与 Provider 行为

1. 增加会话列表、创建、切换、重命名、删除及删除确认；增加消息分页/排序与多轮上下文，范围限定在当前会话消息。
2. 实现 OpenAI Chat Completions 兼容 HTTP/SSE Provider，明确 UTF-8/SSE 边界、超时、HTTP 错误、断流和上游取消。fake server 覆盖分片、异常和取消，不依赖外网。
3. 定义稳定的 `delta`、`completed`、`failed`、`cancelled` 状态；用户消息在请求前落库，assistant 仅在成功完成后落为完整回答。停止/切换会话取消旧请求，迟到事件不得写入其他会话。
4. 设置连接测试可取消；聊天 POST 不自动重试。敏感日志和 Provider 错误响应不得暴露 key、授权头或完整消息正文。
5. 验收本阶段交付物：前端、Provider、SQLite 定向测试覆盖会话 CRUD、多轮上下文、流式、停止、错误、会话切换竞态及重启恢复。

### 阶段 3：运行时随包交付与安全收敛

1. 以已通过的最小纵向闭环为依据，判断本机聊天服务是否确需独立后端进程。若 Rust/Tauri 进程内实现满足需求，不额外引入 Python；若使用现有 Python 生态有明确必要，才验证冻结/嵌入方案。无论选哪条路线，最终用户均不得安装 Python/WSL。
2. 只对实际选定路线做最小 Windows x64 打包 Spike：验证资源定位、启动/健康、停止、异常退出、安装包体积和许可证；不再把“先完整比较所有路线”作为前置任务。
3. 新服务仅监听 loopback，采用随机端口/短期令牌/实例校验并拒绝重定向；CSP 和 Tauri capability 只开放新 UI 所需的调用。验证端口冲突、启动失败、关闭和异常退出，不影响无关进程。
4. 验收本阶段交付物：Windows release 构建可从安装资源启动新聊天功能；静态/自动化检查确认无旧 WSL 探测、旧 Worker 或旧数据库初始化。

### 阶段 4：Windows 产品化与发布验收

1. 将 MVP 窗口标题、首屏路由、图标、NSIS 资源和卸载设置收敛为普通聊天产品体验；新构建默认只进入新聊天 UI，不注册/执行旧 WSL 命令。
2. 编写 Windows 使用说明，明确系统要求、首启模型配置、数据/凭据位置、备份、网络错误和卸载行为。卸载默认保留用户数据，不静默删除。
3. 执行分层验证：后端/原生/前端目标测试、`pnpm build`、Rust `cargo test --locked`、Windows MSVC release/NSIS 构建。只有此阶段对干净 Windows 普通用户环境执行安装、启动、配置、对话、重启恢复和卸载保留数据验收。
4. 真实 Provider 验收为发布验证项，不是开发启动门槛；使用用户明确提供的测试配置和显式 opt-in，限定请求预算。没有凭据或网络时标记为未验收，不由 fake Provider 替代。
5. 发布判定仅依据本计划的 MVP 验收标准。旧 WSL 版本历史上通过或失败均不计入新版证据；所有十个保护文件仍需保持其原有用户改动。

## 风险与决策门槛

- **运行时路线与打包体积：** 先以最小纵向闭环证明实际需求，再验证被选路线；若 Python 打包负担不必要，优先采用进程内 Rust 实现，不能退化为要求用户安装 Python/WSL。
- **凭据库在无登录/远程桌面环境行为差异：** 在 Windows 原生凭据适配器测试覆盖系统库不可用、权限拒绝和凭据缺失，错误时停止发送，不明文回退。
- **SSE 断连导致消息事实不清：** user 消息在 Provider 请求前持久化；assistant 只在正常结束后写为完整答案，失败/取消状态以明确消息状态字段或事件记录保存。恢复后不把半截回复冒充完成回答。
- **Provider 协议兼容差异：** MVP 严格限定 OpenAI Chat Completions 兼容 HTTP/SSE，不承诺所有厂商兼容；需单独 Provider 适配时更新范围。
- **旧 WSL 改动交叉冲突：** 所有已有脏改动由用户所有，按保护基线逐项保留；不做 reset/clean/delete。共享文件冲突无法通过新增式最小补丁解决时，先停下并报告。
- **旧/新本地数据相互污染：** 使用新的 `TomatoAgent` 桌面数据子目录或独立数据库文件；不迁移现有 Agent/Knowledge 数据库，不自动导入会话。
- **网络错误重试重复计费：** 不自动重试聊天 POST；停止和断线的语义在协议中显式区分，用户重试须新操作并清楚可见。

## 计划外结论

本计划制定阶段不运行代码测试。实施阶段的真实模型与干净 Windows 安装验收需具备相应 Windows 环境和用户提供的 Provider 配置；这两项不得从 Linux 构建或 fake server 测试推断通过。计划文档和开发日志按项目规则保持未提交状态。

## 目标

在现有统一助手 Runtime 中建立版本化结构化决策协议和可恢复的运行事件轨迹。模型决策表达阶段性消息、用户输入请求、能力发现/描述、工具调用和完成提议；服务端负责校验、执行、权限、状态推进，并在真实状态变化时写入独立 Runtime 事件。事件记录为未来 UI 流式时间线、简略摘要和可展开详情保留扩展空间，但本计划不实现前端流式传输。

## 架构约束

- 继续以现有 Run、AssistantExecutionSnapshot、RunEvent、执行操作账本、租约/fencing 和共享预算为事实来源，不增加平行事件存储。
- 决策协议与 Runtime 展示/审计事件是不同对象。模型决策是受严格校验的输入；Runtime 事件由服务端根据已发生的状态变化产生。
- `message` 是阶段性总结，不结束 Run；连续消息受既有 Run 预算及无进展保护约束，不要求每条消息伴随工具事件。
- 操作开始事件只能在服务端已验证并实际启动操作后产生。等待、未开始、失败、未知和成功状态必须区分。
- 事件追加保存且有版本。操作状态变化以关联同一调用身份的后续事件记录，不覆写或删除既有审计事实。
- `finish` 是唯一正常完成决策；完成门禁只校验 Runtime 协议与执行闭环，不评判任务/答案质量。
- 未知副作用不得自动重放；按设计进入核查 interrupt 并隔离冲突副作用。

## 风险与处理

- **旧事件读取兼容**：先确认当前 Run API 和事件序列化行为；采用向后兼容可忽略字段/事件。若需更改既有 schema 或 UI 依赖，暂停该切片并单独决定版本协商，不批量改写历史。
- **事件与操作事实重复**：RunEvent 提供 Run 时间线与恢复诊断，操作账本保留工具执行事实。通过关联 ID 投影展示，不把事件投影复制成另一套执行账本。
- **事件时机错误**：只有真实状态转换后才追加对应事件，事件和状态更新尽量共享事务；外部副作用与 SQLite 无法原子提交时继续使用现有未知结果安全策略。
- **详情泄露**：事件摘要和详情均按数据最小化及脱敏要求处理；不默认存储完整凭据、环境变量或未筛选 Provider 原文。
- **UI 需求扩大**：本计划验证后端事件顺序与恢复读取，不以模拟 UI 流式效果替代实际流协议验收。
- **长时协议兼容未定**：本期不承诺部署升级后对所有旧协议快照自动迁移；开工前必须确认至少对未知快照版本拒绝猜测恢复，并确定旧版助手快照的最小读兼容范围，否则先单列兼容策略决策。

- 六类决策均有严格 Schema 与明确状态转换；裸文本和非法决策不结束 Run。

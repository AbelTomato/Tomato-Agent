# Agent 系统 Harness 与 Infra 演进路线图（计划日期：2026-09-26）

> **定位：** 面向简历展示的个人工程项目；以真实任务、故障验证和对照实验体现工程深度，不建设大而全的商业平台。
> **文档性质：** 阶段级规划，不是逐文件实施清单。进入每一阶段前再细化必要接口、测试与验证命令；不一次性实施全部阶段。

## 1. 目标与当前起点

**目标：** 从知识研究与技术写作应用，逐步形成可控、可恢复、可评测的 Agent Harness，以及有实测依据的执行基础设施。

三层责任：
- **Agent Harness：** 管理任务上下文、模型决策、工具权限、预算、停止条件和人工确认。
- **Evaluation Harness：** 用固定任务、执行轨迹、产物校验与人工判断评估系统行为及策略收益。
- **Agent Infra：** 管理执行所有权、持久化、调度、故障恢复、资源限制和运行观测。

**当前状态（同步日期：2026-10-11）：** 写作已实现研究→提纲确认→草稿生成→确认保存的工程闭环；2026-10-07 默认应用的 Alembic 窄主题研究、确认与草稿样例经人工验收通过，样例停在等待保存确认，未调用保存 API。Harness 阶段二已有工程测试及 5 题真实策略对照；研究与写作生产路径的公共 Harness 接入证据仍不充分。代码任务已在固定 `python_calculator` fixture 上完成 SQLite 持久化执行、租约/fencing、独立进程故障恢复、单机单 Worker 后台调度、异步 API、前端操作面及受限 OpenShell 故障验收；2026-10-11 交付门禁记录后端目标回归 133 passed、6 个真实 opt-in 场景跳过，前端 5/5 与 TypeScript/Vite 构建通过。当前仍限本地可信单用户和单 Worker，不代表写作已接入同一恢复内核，也不代表多 Worker、生产规模或完整外部故障矩阵已验收。此处引用已有验收记录，本次状态同步未重跑测试或外部调用。

首期详细计划：`docs/实施计划/2026.09.26-技术写作任务执行器首期实施计划.md`。
当前行为说明：`docs/guides/技术写作Agent说明.md`。
首期研究执行器计划与完整写作闭环的工程实施已完成；历史 Transformer 样例质量失败仍保留，后续 Alembic 单样例通过不证明普遍质量或浏览器完整交互验收。当前状态以各说明文档中的最新验收章节为准，历史执行记录保留原日期与证据边界。

**原则：** 业务做窄，执行底座做深；先保证一个真实闭环，再抽象复用，再做并发验证。沿用现有 FastAPI、Python、Pydantic、SQLite 和 React 技术栈，不预先锁定新增中间件。

**OpenShell 融合定位：** 将 OpenShell 作为后续可选的安全执行后端/Agent Infra 候选，通过独立 Adapter 与 Tomato-Agent 对接；不将其作为 Agent Harness、RAG、业务任务状态机或用户确认流程的替代品。优先复用其 Sandbox 生命周期、Supervisor、文件/进程/网络策略和凭据边界；是否进入默认执行路径由阶段性实验决定。当前已有 Docker/OpenShell CLI Adapter 及独立获批的本地真实验收；完整生命周期、资源边界和生产能力仍未验收。本路线图不额外授权部署、外部调用或新增依赖。

## 2. 阶段总览

| 顺序 | 阶段                       | 核心产物                             | 进入下一阶段的依据                  |
| ---- | -------------------------- | ------------------------------------ | ----------------------------------- |
| 1    | 完整写作闭环               | 确认提纲→生成草稿→校验→确认保存      | 端到端链路及真实样例验收            |
| 2    | Harness 核心与受控自主研究 | 共享执行策略、上下文、工具能力声明及单工具 Sandbox 适配实验 | 两类任务复用；自主策略有对照结果；Sandbox 接口与策略失败边界明确 |
| 3    | 持久化执行与恢复           | 执行尝试、所有权、操作记录、恢复规则及 Sandbox 执行关联 | 故障注入与重复副作用验证；不混淆业务状态与 Sandbox 状态 |
| 4    | 最小 Infra 与后台调度      | API/Worker 分离、调度与资源治理；按验证结果选择 Local/OpenShell 执行后端 | 多 Worker 实验不破坏阶段 3 的正确性；Sandbox 归属及清理可审计 |
| 5    | 规模验证与工程交付         | 负载/故障/安全对照报告、可复现部署、演示材料  | 能明确说明容量、限制、OpenShell 运维成本与取舍 |

评测、观测与安全是贯穿各阶段的工作，不等到最后补齐。没有硬性日历承诺，以验证结果决定推进。

### 阶段 3：持久化执行与故障恢复

**代码任务窄范围增量（2026-10-10 历史验收）：** SQLite 持久化执行内核任务 1～6 完成；新增独立进程硬崩溃测试 10/10 通过，执行/代码任务/Harness 相关 15 文件组合 158/158 通过。已验证模型响应恢复、步骤提交事务前后、终态提交、预算延续、竞争领取及失效执行者拒绝；未知文件/Sandbox 副作用保持 waiting，取消不冒充资源清理。此项按独立获准计划推进，不代表研究/写作生产路径门禁、整个阶段三或阶段四完成；当时尚无后台调度、真实外部故障矩阵或业务库迁移证据。后续单 Worker 后台验收见阶段四，历史测试数字不与最新回归累加。

**当前范围（2026-10-11）：** 代码任务持久化执行内核的独立计划已完成；研究/写作尚未整体接入。下列清单按各项完整范围标记，迁移版本框架、未知 Artifact reconcile、完整 Sandbox 状态关联与真实外部故障矩阵仍保留未完成，不将代码任务窄范围验收视为整个阶段三完成。

**依赖：** 执行阶段、模型/工具边界已明确；先做受控执行者的正确性，不立即铺开多 Worker。

- [ ] 明确 Task/Run、Attempt、Step、工具操作记录各自语义，复用已有记录并制定版本迁移规则。
- [x] 定义领取、运行、等待人工、完成、失败、取消的合法迁移；定义租约/执行令牌，拒绝失效执行者提交。已在执行内核及代码任务范围验证，研究/写作接入另行验收。
- [x] 按只读、幂等写入、结果未知且不可安全重试三类设计恢复策略；有稳定操作 ID，必要时核对外部结果或转人工。代码任务未知副作用保持 waiting，自动外部结果 reconcile 尚未完成。
- [x] 持久化已完成步骤产物和预算消耗；恢复不无限重置预算，等待人工不持续占用 Worker。完成范围为代码任务执行快照与产物引用。
- [x] 用故障注入覆盖模型返回前后、工具完成但未记结果、事务提交前后、取消与完成竞争、重复投递和旧执行者返回。已有 fake 模型/工具及独立进程测试，不替代真实外部故障矩阵。
- [ ] 若阶段 2 OpenShell 试点通过，定义持久化 `SandboxExecution` 与 Task/Run/Attempt/Step 的关联：记录 sandbox 标识、执行所有者/租约令牌、policy revision、镜像/运行时、输入输出摘要、退出状态及取消结果；凭据和原始敏感内容不得进入普通执行事件。
- [ ] 将“业务 Attempt 状态”和“Sandbox/进程状态”建模为两个相关但独立的状态域；验证 Sandbox 已退出但业务提交未完成、Gateway 断连、超时/取消、Sandbox 遗留等场景的恢复及清理策略。

**验收：** 中途终止执行进程后，已完成阶段可被识别；可重试阶段按策略继续，未知副作用不被盲目重放；失效执行者不能覆盖新结果。明确记录保证范围，不承诺任意外部工具 exactly-once 或零重复模型费用。若使用 OpenShell，Sandbox 重建/保留/清理策略与业务重试策略分别验证，不把 Sandbox 存活视为任务仍有执行所有权。

### 阶段 4：最小 Infra 与后台执行

**当前状态（2026-10-11）：** [代码任务后台执行与可恢复操作闭环计划](2026.10.10-代码任务后台执行与可恢复操作闭环实施计划.md)任务 1～6 已完成功能与目标交付验收，后续切片提交步骤按计划记录仍未完成。单 Worker 生命周期、异步提交、状态/事件游标、取消、人工恢复确认、前端报告/diff 查看均已有证据。后台 HTTP/独立进程六场景使用脚本模型及真实 OpenShell，清理失败为显式注入；浏览器 waiting 检查使用未知副作用夹具，真实 Sandbox 上传后硬退出重启保持 waiting 另有独立证据。该子集不满足本节完整多 Worker 验收标准。

**依赖：** 阶段 3 的领取、重试、提交和取消语义经过测试；再增加并发执行者。

- [x] 将提交任务、查询状态与实际执行分离，加入持久化调度、Worker 和人工确认后的重新调度。完成范围为代码任务、单机单 Worker；未知副作用即使确认也保持 waiting，不盲目重放。
- [ ] 补齐并发上限、排队/背压、Provider 限流、分类重试、积压与失败任务处理。
- [ ] 定义 API 与执行环境的最小身份、资源归属和权限控制；错误资源 ID 不能访问他人任务或产物。
- [ ] 记录模型 usage、估算成本与预算消耗；明确 Provider 缺少计量数据时的未知项，不伪造计费精度。
- [ ] 通过负载和锁竞争数据决定是否迁移数据库、引入队列或外部产物存储；选择一个最小方案，保留迁移和恢复路径。
- [ ] 将 OpenShell 接入限定为可替换的执行后端：Tomato-Agent Worker 负责领取业务 Attempt、预算和提交业务结果；OpenShell Gateway/Supervisor 负责 Sandbox 生命周期及系统层执行约束。保存 Task/Run/Attempt/Step/SandboxExecution/Trace 的关联与策略版本。
- [ ] 评估 OpenShell Gateway API/SDK 的认证、可用性、超时、取消、事件/日志读取、Artifact 上传下载、幂等创建和 Sandbox 清理契约；先用隔离环境与假后端完成契约测试，再进行获批的真实集成验证。
- [ ] 若引入 Sandbox Worker，验证执行身份最小权限、策略版本绑定、输入输出工件白名单/摘要、并发/资源上限、孤儿 Sandbox 回收和控制面不可用时的失败关闭行为；不得把宿主路径、环境变量或凭据无差别传入 Sandbox。

**验收：** 至少两个 Worker 的受控实验覆盖并发领取、重复投递、执行者退出和限流；任务状态正确、有背压、不形成无限重试。若接入 OpenShell，另验证 Sandbox 所有权、策略拒绝、取消/超时、断连恢复和遗留 Sandbox 清理；没有这些证据，不宣称多机或生产规模可用。

**边界：** 不建设商业计费、插件市场、复杂多租户管理或全套微服务。若扩展任意代码/外网工具，必须先补进程/文件/网络隔离，不以函数超时代替沙箱。OpenShell 是候选实现而非唯一选项；不得为集成重写业务 Agent/RAG、把 SQLite 业务数据库直接暴露给 Sandbox，或将网络/凭据策略交由模型任意生成。

### 阶段 5：规模验证、可复现交付与简历材料

**依赖：** 最小 Infra 稳定，工作负载和验证环境明确。

- [ ] 分别使用模拟 Provider 和获批真实 Provider 做负载实验；先从 1/10/50 并发探索，不把这些梯度作为预先承诺的容量。
- [ ] 报告成功率、系统错误率、排队时间、p50/p95 完成延迟、吞吐、恢复耗时、重复副作用及每成功任务消耗。
- [ ] 对固定任务集比较 LocalExecutor 与 OpenShellExecutor：除业务质量、成本和时延外，记录 Sandbox 启动/回收开销、策略拒绝行为、文件/网络隔离验证、故障恢复和运维复杂度；只有安全收益与成本有证据时才决定默认后端。
- [ ] 记录机器配置、数据规模、模型、任务长度、运行时长与故障条件，区分 Provider 限制和本地瓶颈。
- [ ] 建立最小 CI：目标测试、契约检查、无外部调用的确定性回归；整理环境配置、部署、数据迁移、备份恢复和关闭流程。
- [ ] 输出三段演示：真实任务闭环、执行故障恢复、Harness 策略对照；配套架构图、关键设计决策及已知限制。

**验收：** 在记录的环境中可重现演示和报告。简历只写已验证能力与真实测量值，不能把本地并发实验描述成真实线上用户规模。

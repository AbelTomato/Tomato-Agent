# 桌面项目多目录与普通聊天（计划日期：2026-10-20）

## 目标

调整 Windows 桌面端的项目、目录和聊天模型，使用户能够创建包含多个 Windows 文件夹的项目；项目会话默认访问项目中的全部目录；普通聊天无需项目或目录，并可在会话中按需添加目录。WSL 是可配置执行环境，而不是开始聊天或使用应用的前置条件。

## 已确认需求

- 创建项目时填写项目名称，并通过 Windows 文件夹选择器添加一个或多个源文件夹。
- 同一个 Windows 文件夹可以被多个项目引用。
- 项目会话默认可以访问该项目包含的全部源文件夹。
- 普通聊天无需项目或目录即可创建会话并对话。
- 普通聊天可在会话期间添加目录；目录只附加到当前会话，不自动创建项目，也不影响其他会话。
- Windows 文件夹选择器允许选择任意 Windows 文件夹。
- 服务运行在 WSL 时，由应用负责把 Windows 路径映射为 WSL 可访问路径。
- 工作区是内部执行和授权概念，不作为用户开始聊天、创建项目或添加目录的前置配置。
- WSL 及后端服务连接设置保留为可选配置项。

## 术语与模型

- **项目**：用户可见的组织对象，包含名称和零个或多个源文件夹引用。
- **源文件夹**：用户通过 Windows 文件夹选择器授权的 Windows 目录。多个项目可以引用同一目录。
- **会话**：可关联一个项目，也可以不关联项目。普通会话可附加会话级目录。
- **工作区**：后端执行层使用的授权目录范围。工作区标识和路径转换由应用维护，不要求用户手动配置。
- **执行环境**：承载后端服务的运行环境，例如 Windows 原生或 WSL。

路径映射与权限检查必须分离：路径可转换不代表已授权；任务只能访问当前会话明确关联的项目目录或会话目录。

## 架构方案

Windows 桌面端使用 Tauri 原生目录选择能力取得 Windows 文件夹路径。桌面路径桥接层根据活动执行环境将路径解析为后端可访问的规范路径，并返回明确的可用/不可用结果。项目与会话目录授权由后端持久化并校验，任务只能在有效授权集合内解析文件。

后端将项目元数据与项目目录关联拆分存储；项目会话的有效目录集合由项目目录关联派生，会话临时目录单独保存。创建任务时固化本轮有效授权集合，避免后续项目或目录变更静默扩大正在执行任务的访问范围。现有单根工作区 API 可通过适配层兼容，不继续作为桌面端项目的用户模型。

## 范围

包含：

- 项目名称及多目录关联的数据模型、API 和前端管理。
- Windows 原生目录选择及 Windows 到 WSL 的路径桥接。
- 普通会话无项目启动。
- 会话级目录添加、查看、移除及任务授权。
- 项目侧栏、创建项目弹窗、聊天输入区和来源区域的 UI 调整。
- 执行环境设置与工作区内部模型解耦。
- 现有桌面单目录项目数据的兼容读取或可审计迁移。
- 相关文档和测试更新。

不包含：

- 任意 shell 命令或任意文件系统访问授权。
- 项目目录自动同步、复制或迁移。
- 自动部署后端、自动安装依赖或修改用户环境。
- 将多个目录合并为一个物理工作区。
- 让模型自行发现或扩大授权目录范围。

- `frontend/tests/`、`backend/tests/`、`desktop/src-tauri/src/`：覆盖 UI、API、迁移、路径桥接及安全边界。
- `docs/archive/windows/Windows桌面连接与生命周期.md`、`README.md`：回填项目、目录、聊天和环境配置语义。

## 分阶段任务

### 阶段一：多目录项目领域模型与迁移

状态：已实现。项目元数据存入 `desktop_project_metadata`，项目目录关联存入 `project_directories`；启动时将旧 `desktop_projects` 记录按原 `project_id`、名称、workspace、目录路径及文件系统身份幂等迁入。旧 `/api/projects/open` 和根目录项目创建/列表接口保持兼容，新元数据/目录操作位于 `/api/projects/metadata`。阶段一定向服务与新 API 验证通过；旧全量 API 和 session 测试因当前工具 30 秒执行上限未取得结果，需在后续阶段回归时重新验证。

1. 将项目元数据与项目目录关联分离。项目包含名称及零个或多个目录引用；目录引用可被多个项目复用。
2. 为新增、移除、重复添加、项目重命名、目录不可用建立服务层规则；移除引用不得删除或移动用户源文件夹。
3. 将既有单根项目记录迁移为一个项目及一个目录关联，保留项目 ID、会话关联和旧目录；迁移需支持重复执行。
4. 保持旧 API 的必要兼容性，直至桌面端改用新接口。
5. 增加仓储、服务和 API 测试：多目录关联、跨项目共享、幂等、迁移重复执行、目录不可用和旧接口兼容。

验证：从 `backend` 执行 `.venv/bin/pytest tests/test_projects_api.py tests/test_session_titles.py -q`，并运行新增的项目仓储/服务定向测试。

本阶段实际验证：`.venv/bin/pytest tests/test_projects.py tests/test_project_metadata_api.py -q`（14 passed）；项目/API 文件 `py_compile` 通过。计划指定的旧 API/session 组合测试以及旧 API 单节点测试被执行工具 30 秒上限中断，未判定通过。

### 阶段二：Windows 文件夹选择与路径桥接

状态：目录选择器与本地盘符路径桥接已实现，WSL/Windows MSVC 单元测试与 Windows release 构建通过；Windows 原生窗口中的目录选择及 WSL 实际访问验收待用户人工操作。桌面设置增加 Windows 原生文件夹选择与映射检查；桥接仅接受本地盘符路径，使用固定 `wsl.exe` 参数调用 `wslpath -u` 并对比 `/mnt/<drive>/...` 规范映射，再用 WSL `test -d` 核验可访问性。UNC、相对路径、父级跳转、控制字符、映射不一致及不可用目录明确拒绝。该检查只验证候选路径，不添加项目/会话授权。Windows 应用已启动，但首次打开工作区因保存的后端路径指向仓库根目录而启动失败；人工验证前应在设置中将其改为 `backend`。此连接问题不影响单独使用设置中的目录选择/桥接检查。

本机验证：桌面 Rust 单元测试 WSL 16/16、Windows MSVC 16/16；前端连接设置/桌面连接测试 4/4；`pnpm build` 通过。Windows 应用构建及原生目录选择的人工验收结果另行记录；测试通过不等同于 Windows UI/路径访问验收完成。

1. 核实 Tauri 2 当前依赖及 Windows 构建能力后，接入原生目录选择器；允许用户选择任意 Windows 文件夹。
2. 新增独立路径桥接模块，区分 Windows 原始路径、规范路径和后端可访问路径。
3. WSL 模式下实现经验证的 Windows 驱动器路径映射，例如 `C:\\dir` 到 `/mnt/c/dir`；明确处理空格、Unicode、大小写、网络/UNC 路径和不可映射路径。
4. 不以 shell 字符串拼接执行路径转换；使用固定程序、参数数组及受限命令。
5. 对不存在、拒绝访问、符号链接/重解析点、映射歧义和越权路径返回可区分错误。
6. 目录选择只取得路径，不自动授权访问；只有加入项目或会话后才进入任务授权范围。
7. 增加路径映射单元测试和 Windows 实机测试；无法映射的路径明确拒绝，不静默降级。

验证：在 `desktop/src-tauri` 执行 `cargo test`；Windows 实机验证原生选择器、驱动器路径、Unicode/空格路径及 WSL 实际可访问性。Linux/WSL 测试不得代替 Windows 原生验收。

### 阶段三：会话级目录授权与无项目聊天

1. 新会话创建不要求项目、目录或工作区。
2. 为会话目录提供添加、列出、移除操作；会话目录仅作用于当前会话。
3. 项目会话的有效目录集合由所属项目的目录关联生成；普通会话由其显式添加的会话目录生成。
4. 任务启动时固化授权集合；项目或会话目录后续变化不扩大已运行任务权限。
5. 助手文件读取、代码执行和验证入口只能解析当前任务授权集合中的路径；无目录聊天仍可进行不访问项目文件的对话，需要文件访问时提示用户添加目录。
6. 增加 API/集成测试：无项目普通聊天、会话目录隔离、项目多目录授权、启动快照、目录移除后新任务权限更新、越权拒绝。

## 全局约束

- 默认在主工作树 `仓库根目录` 实施，不创建分支或 worktree。
- 实施前逐个核对目标文件当前差异；保留所有既有未提交修改，不覆盖无关内容。
- 后端命令从 `backend` 执行，并使用 `.venv/bin/` 中的解释器。
- 不将测试数据写入 `backend/data/agent.db` 或 `knowledge.db`。
- 普通聊天、项目创建和目录选择不隐式启动 WSL 服务；只有用户明确配置并触发连接时才连接。
- 不记录认证 Token、Authorization Header 或其他凭据。
- 路径转换成功不等于授权成功；文件访问必须受项目/会话授权集合约束。
- 不自动安装依赖；新增 Tauri 依赖前先确认必要性、Windows 构建可行性和锁文件变更。
- 本计划和开发日志位于项目配置的 Git 忽略目录，不通过强制添加方式提交。

## 风险与缓解

| 风险 | 缓解方式 |
| --- | --- |
| Windows 到 WSL 路径映射存在网络盘、UNC、权限和大小写差异 | 定义受支持路径类型；对不可映射路径明确拒绝；以 Windows 实机结果验收 |
| 多目录实现误扩大助手访问范围 | 将路径映射与授权分离；任务创建时固化目录授权；增加越权集成测试 |
| 现有单工作区接口与项目多目录不匹配 | 先完成领域关联和任务授权适配，再迁移 UI；不在前端拼接多个路径冒充工作区 |
| 旧项目数据迁移导致项目或会话丢失 | 保留项目 ID、会话关联和旧根路径；迁移可重复执行并覆盖回归测试 |
| 原生文件夹选择依赖未声明的 Tauri 能力 | 先核实依赖与 Windows 构建；不自动安装全局工具或更改系统 |
| 当前 UI/连接文件含用户未提交改动 | 实施前查看差异并在现状上增量修改，不重置或覆盖 |
| Windows 实机环境不可用 | 可完成定向测试和构建，但明确标记原生选择器/映射验收未完成 |

## 验收标准

- 新用户可直接创建普通聊天，无需先选项目、工作区或 WSL。
- 普通会话可按需添加多个 Windows 文件夹，授权仅影响该会话。
- 项目可包含多个源文件夹；项目会话默认获得该项目的目录集合。
- 同一个文件夹可被多个项目引用；移除引用不会删除或移动源文件夹。
- WSL 配置不出现在创建项目和普通聊天的必经流程中。
- WSL 模式下 Windows 文件夹可以映射为后端路径；映射失败或未授权时明确拒绝访问。
- 重启桌面端后项目、目录关联、会话关联和环境偏好可恢复。
- 相关定向测试和构建通过，并完成 Windows 原生 UI 与路径访问人工验收。

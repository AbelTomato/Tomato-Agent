## 3. 固定契约

### 3.1 提纲输出

新增 `backend/app/writing/execution_models.py`，定义：

- `OutlineSection`：`title: str`、`points: list[str]`、`citation_ids: list[str]`。
- `GeneratedOutline`：`title: str`、`sections: list[OutlineSection]`、`gaps: list[str]`。
- `ExecutionConfig`：`retrieval_mode: Literal["keyword", "vector", "hybrid"] = "keyword"`，`max_evidence=5`（1–10）、`max_context_tokens=8000`（正数）、`max_response_chars=20000`（正数）、`timeout_seconds=120.0`（正数）。所有限制为初始工程默认值，不是性能或计费承诺。
- `ResearchBundle`：`evidence_status` 复用现有 `EvidenceStatus`、`citations: list[CitationSnapshot]`、`retrieval_mode`。
- `ExecutionAttempt`：见 3.3 的持久化字段。

提纲模型使用 `ConfigDict(extra="forbid", strict=True)`。title 去空白后 1–200 字符；sections 1–12 项；每节 points 1–8 项，每项去空白后 1–1000 字符；每节至少 1 个非空且不重复的 citation_id；gaps 0–12 项，每项 1–500 字符。模型不得返回业务 status、saved_path、task_id 或用户确认字段。

示例（是输出契约，不是默认生成内容）：

```json
{
  "title": "Redis 过期机制",
  "sections": [{
    "title": "设置过期时间",
    "points": ["解释 SETEX 对值与过期时间的设置"],
    "citation_ids": ["chunk-1"]
  }],
  "gaps": ["当前材料未覆盖淘汰策略与过期机制的区别"]
}
```

定义纯函数 `validate_outline(raw: str, citations: list[CitationSnapshot], *, max_response_chars: int = 20000) -> GeneratedOutline`：先限制响应长度，再严格 JSON 解析和 Pydantic 校验；拒绝 Markdown 围栏、重复 JSON key、NaN/Infinity、额外字段、空字符串、未知引用及相同 citation_id 对应不同快照。所有引用必须来自实际传给生成模型的证据包。不得相信模型返回的来源路径、行号或正文。

结构与引用归属校验不证明语义支撑。`gaps` 是模型声明的缺口，不等同于系统验证过的覆盖率。

### 3.2 检索与生成接口

新增 `backend/app/writing/research.py`：

- `WritingResearcher(knowledge_service: KnowledgeService)`。
- `async collect(topic: str, *, config: ExecutionConfig) -> ResearchBundle`：调用一次 `retrieve(topic, mode=config.retrieval_mode, limit=config.max_evidence)`，复制正文快照；不在生成后重新读取来源。
- 依赖装配创建写作专用 `KnowledgeService`，`pipeline=None`；沿用现有 Embedding 配置与阈值。不得复用可能启动 QueryPlanner/Reranker 的线上 pipeline 实例，否则“一次检索/一次提纲 LLM”的预算不成立。
- `keyword` 不访问外部服务；`vector/hybrid` 至多一次 query embedding 调用。写作默认请求 `hybrid`；缺少 Embedding 客户端/配置或向量索引模型、维度不兼容时，仅 `hybrid` 允许显式回退 `keyword`，并记录实际模式和稳定回退原因；Provider 网络、认证和超时错误继续失败。默认 keyword 无证据是合法失败，不为了演示成功扩大查询或模型预算。

新增 `backend/app/writing/outline.py`：

- `build_outline_messages(topic: str, citations: list[CitationSnapshot]) -> list[Message]`：系统消息固定规则，主题与证据放入单独数据消息，明确不可信；不添加其他 Session 聊天、Memory 或客户端系统指令。
- `select_outline_context(topic: str, citations: list[CitationSnapshot], *, max_context_tokens: int) -> tuple[list[Message], list[CitationSnapshot]]`：使用现有 tiktoken `cl100k_base` 计算完整序列化消息的本地 token 估计，按原顺序保留完整证据块。超限从尾部移除整个块，不截断正文后保留原行号；最小消息仍超限或零块可容纳则失败。此估计不是 Provider 精确 token 或费用上限。
- `OutlineGenerator(llm: LLMClient)`，`async generate(topic: str, bundle: ResearchBundle, *, config: ExecutionConfig) -> tuple[str, list[CitationSnapshot]]`：选择上下文后，调用一次 `llm.complete(messages, tools=[])`。只接受 kind=final；tool_call/clarification、无内容均报稳定错误。返回原始响应文本及实际传入模型的完整证据集合，由执行器进入 validation 阶段后调用纯函数验证。
- `no_results`、`insufficient` 或空 citations 时不调用提纲模型，失败码为 `evidence_insufficient`；不发布空提纲。非空 supported 仅表示检索门禁允许生成，不代表语义质量通过。

### 3.3 尝试与数据库

业务状态仍用原枚举。新增 `writing_attempts` 表，不新增第二套 Session/Run 表：

```sql
CREATE TABLE IF NOT EXISTS writing_attempts (
    attempt_id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL REFERENCES writing_tasks(task_id),
    input_version INTEGER NOT NULL,
    run_id TEXT NOT NULL UNIQUE REFERENCES runs(id),
    status TEXT NOT NULL CHECK(status IN ('running','completed','failed','conflicted')),
    phase TEXT NOT NULL CHECK(phase IN ('retrieval','generation','validation','publication')),
    error_code TEXT,
    config TEXT NOT NULL,
    model_id TEXT NOT NULL,
    prompt_version TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE(task_id, input_version)
);
```

`ExecutionAttempt` 对应上述字段（ID 为 UUID、时间为 UTC datetime、config 为 ExecutionConfig）；不记录 API key、请求头、原始异常、完整提示词或未经校验的模型输出。prompt_version 首版固定 `writing-outline/v1`。执行中的 phase 是排障进度，不是可恢复 Checkpoint。

新增 `backend/app/writing/execution_repository.py`，使用与 WritingRepository 相同 SQLite 路径；SessionRepository/WritingRepository 初始化后才初始化此表。每个连接启用外键。

接口：
- `async init() -> None`：幂等建表，仅在允许的应用启动/测试初始化中执行。
- `async get_attempt(task_id: UUID, input_version: int) -> ExecutionAttempt | None`。
- `async get_latest_attempt(task_id: UUID) -> ExecutionAttempt | None`。
- `async start_attempt(task_id: UUID, *, expected_version: int, config: ExecutionConfig, model_id: str) -> ExecutionAttempt`。
- `async set_phase(attempt_id: UUID, phase: str) -> None`：仅允许 running，phase 限上述枚举。
- `async complete_attempt(attempt_id: UUID, *, outline: GeneratedOutline, citations: list[CitationSnapshot]) -> WritingTask`。
- `async fail_attempt(attempt_id: UUID, *, error_code: str) -> WritingTask`。

start 使用短 `BEGIN IMMEDIATE` 事务：确认任务 researching 且 version 精确匹配；同事务插入真实 runs 行（遵守现有字段结构、初始 running）和 attempts 行，随后提交。网络调用不在事务内。UNIQUE(task_id,input_version) 防止相同版本重复启动；不解释为多 Worker 调度能力。

complete/fail 首先在事务内核验 attempt 仍为 running 且对应 Run、task/session 关联一致；已终态的 attempt 不再修改。complete 使用一个短事务：按 task_id/input_version/researching 条件更新 writing_tasks 的 outline/citations/research_run_id/status/version，同时将 attempts、runs 标记 completed。`version=input_version+1`，写作状态 awaiting_outline_confirmation。任何一步失败全部回滚，不使用多个 repository 方法拼成“伪事务”。Run state 只保存 task_id、attempt_id、阶段和结构化结果索引，不写 assistant_message 事件，因此不进入普通聊天历史。

fail 同事务更新 attempt/run 失败以及 task failed、failed_stage=researching、version+1。实际子阶段和稳定错误码放在 attempt；保持现有 retry() 只认 researching/drafting 的兼容性。

若 complete/fail 发现任务已变化：不改任务，仅将仍 running 的旧 attempt 标记 conflicted、旧 Run 标记 failed（错误码 stale_result），提交后抛 WritingConflictError。不要回滚掉这次冲突记录，也不要通过通用 fail() 覆盖新状态。

不得修改通用 `mark_failed()` 以顺便修复不相关状态迁移；执行器只用上述带 researching 条件的专用提交路径。

### 3.4 执行器与错误契约

新增 `backend/app/writing/executor.py`：

`WritingTaskExecutor(service: WritingService, repository: WritingExecutionRepository, researcher: WritingResearcher, generator: OutlineGenerator, *, config: ExecutionConfig, model_id: str)`。

唯一执行入口：`async execute_research(task_id: UUID, *, expected_version: int) -> WritingTask`。

执行顺序固定：

1. 验证任务存在，查询此 input_version 的 attempt。已完成且仍能关联 task.research_run_id 的请求返回当前任务，不重复检索/模型调用；即使用户已确认提纲也不倒退状态。running/failed/conflicted 返回冲突；failed 先通过现有 retry API 升级任务版本后再执行。
2. 无 attempt 时，只允许 researching 且版本精确相等。调用 start_attempt 原子创建尝试及 Run；进程内可以并发请求，数据库唯一约束是最终防重复边界。竞态输家返回 409，不进行外部调用。
3. 使用 Python 3.11 `asyncio.timeout(config.timeout_seconds)` 包裹 collect、generate、validate 和提交前阶段操作；记录阶段并依序执行，外部调用不自动重试。publication 及失败登记在该超时上下文之外，SQLite 连接 timeout 固定 5 秒；运行预算是生成阶段截止时间，不承诺包含数据库收尾的硬性 HTTP 总时限。
4. 在 validation 阶段调用 validate_outline，成功后进入 publication，调用 complete_attempt 提交；不得调用 confirm_outline、publish_draft 或 save。
5. timeout/模型/检索/校验错误退出超时上下文后调用 fail_attempt，以避免立即被同一超时再次取消。CancelledError 尽力记录 cancelled 后仍需重新抛出，不能当作正常成功。
6. publication 发生数据库异常或取消时，先通过新连接读取 attempt/task/run：三者已成功则保留成功；普通异常路径返回已提交结果，取消路径仍重新抛出 CancelledError。明确仍 running 且事务回滚才尝试登记 publication_failed；无法读取则保持结果未知，普通异常向 API 报 storage_unavailable，取消仍向上传播，不盲目覆盖成功状态。
7. 进程硬退出可能留下 running；再次请求必须冲突，不做自动接管。首版不能通过重置状态假装恢复；后续恢复模块需要单独定义所有权和人工解除流程。

在 `backend/app/writing/execution_models.py` 定义 `WritingExecutionError(code: str)`，只携带下表允许的稳定错误码，不向外转发 Provider 原始异常。保留现有 WritingNotFoundError/WritingConflictError。

| 错误码 | 处理 |
|---|---|
| evidence_insufficient | 检索无证据/insufficient，失败且不调用生成模型 |
| context_budget_exceeded | 主题与必要指令无法容纳，或证据包被全部移除 |
| retrieval_failed | 检索或 Embedding 调用失败 |
| model_unconfigured | 执行前检查，无模型配置；不创建 attempt，不调用外部服务 |
| provider_failed | 模型异常，不存原始响应/错误正文 |
| invalid_model_response | 非 final、空响应、超过长度、非法 JSON/结构 |
| invalid_citation | 未知 ID、重复 ID 或冲突证据身份 |
| deadline_exceeded | 生成阶段期限到达；不包含有界数据库收尾，不等同于 Provider 无计费 |
| cancelled | 协程被取消，尽力登记，不保证硬退出可记录 |
| publication_failed | 已确认提交未发生的持久化失败 |
| stale_result | 老版本执行结果不能提交，新任务状态不动 |
| storage_unavailable | 无法确定提交结果，不自动重试或改写状态 |

预期执行错误登记成功后抛 WritingExecutionError；下一次 GET task 显示 failed。证据不足不能伪装成 HTTP 成功发布，系统也不能据此声称真正无答案。

### 3.5 API 与配置

在 `backend/app/api/writing.py` 添加：

- `POST /api/writing-tasks/{task_id}/research`，请求仅 `{"version":1}`。新模型 `ResearchRequest` 使用 extra=forbid、严格正整数，拒绝 bool、字符串版本及客户端 outline/path/model/预算字段。
- 成功 200，返回既有 WritingTask JSON；等待本次有限时执行完成，不返回 202、不使用 BackgroundTasks。不改变原 create API 为“创建即执行”。
- UUID 非法 400、请求字段校验 422、任务不存在 404、状态/版本/重复运行冲突 409。
- evidence_insufficient/context_budget_exceeded 返回 422；provider_failed/invalid_model_response/invalid_citation/retrieval_failed 返回 502；deadline_exceeded 返回 504；model_unconfigured/storage_unavailable/publication_failed 返回 503。
- 错误体 `detail={"code":"稳定错误码"}`，不暴露 traceback、凭据或模型正文。
- `GET /api/writing-tasks/{task_id}/research-attempt` 返回最新 ExecutionAttempt 的 JSON；任务不存在 404，无尝试 200 + `null`。只暴露本计划字段，不返回额外环境配置。

- 在 `backend/app/settings.py` 添加 `writing_retrieval_mode="hybrid"`、`writing_max_evidence=5`、`writing_max_context_tokens=8000`、`writing_max_response_chars=20000`、`writing_timeout_seconds=120.0`，校验边界与 ExecutionConfig 一致。不增加 Provider 凭据配置。

在 `backend/app/main.py` 装配写作专用 KnowledgeService、researcher、generator、execution repository、executor。初始化顺序在 3.3 中定义。通过 app.state 注入，保持现有测试 monkeypatch 方式。生产模型未配置时 executor 不可用；测试用 FakeLLM 显式注入，不依赖真密钥。不要导入 main 去实现其他模块。

仅在工程验收后，用户确认模型、只读快照、主题及调用范围，才执行。建议固定三个开发主题：有材料、材料不足、跨两段证据；不能使用保留 test 集调参。至多 3 次提纲模型调用、vector/hybrid 时至多 3 次 Embedding 调用，无自动重试。客户端请求数限制不代表费用保证。

研究读取获批只读 RAG 快照；写作任务与 attempts 使用单独验收业务库 `backend/data/writing-acceptance/<run-id>/execution.db`，不与语料库混存、不访问现有业务库。报告写入 `backend/data/rag/reports/2026-09-27/writing-stage1/dev/<run-id>/`，按实际运行日替换日期，新目录不可覆盖。报告只记录获批样例的脱敏材料与产物，不记录凭据。

人工逐项判断：主题覆盖、结构是否可写、逐节引用是否支持要点、缺口是否诚实、是否夹带无证据断言。记录 pass/partial/fail 及理由；验收条件不满足时明确“真实模型质量验收未执行”。不把 FakeLLM 成绩作为生成质量指标，不填写虚构成功率。

## 7. 风险与后续边界

| 风险 | 本期处理与不能承诺的范围 |
|---|---|
| 确定性研究不是自主研究 Agent | 作为可比较基线；后续 Agent Loop 必须用相同任务评测收益 |
| 默认 keyword 对中文主题召回差 | 显式失败或由部署者选择已配置 vector/hybrid；不偷偷切换 |
| 非空检索并不证明材料充分 | Schema/引用归属是机器门禁；语义支撑靠独立人工验收 |
| 响应超长 | 本地拒绝解析超长响应；LLMClient 暂无 max output tokens 参数，不宣称 Provider 输出费用被约束 |
| 模型响应后进程退出 | 未落库响应可能丢失，首版无自动恢复，不能保证零重复费用 |
| 数据库提交结果不确定 | 先核对持久化事实；存储不可读时保留未知，不覆盖成功 |
| 用户修改已生成提纲 | 既有 confirm 接口保持兼容；草稿模块必须重新校验确认后的结构/引用，不假设用户编辑仍符合生成 Schema |
| 遗留手动 publish_outline 接口 | 保持兼容，不作为执行器提交入口；未来统一入口另立变更 |
| API 无完整鉴权 | 可信本地使用，不能作为公开多租户产品部署 |
| 存储协议耦合 | 专用事务依赖现有 runs 表；事务测试固定兼容性，不顺手改造全局仓储 |

下一切片顺序：先实现“已确认提纲→草稿生成与校验→等待保存确认”，随后才设计执行所有权、崩溃恢复与后台调度。本计划完成时不能在简历中声称已经实现完整写作闭环、分布式恢复或规模化能力。

## 方向修订（2026-10-18）

## 全局约束

- 真实 Provider 验收必须显式 opt-in，并保持在常规 CI 之外。
- 本地验收数据写入 `backend/data/runtime-provider-acceptance/` 下每次独立目录；不得写入业务数据库。
- 保留现有全局 Run 和 Provider 请求上限；新增场景预算只能进一步限制，不能自动增加总预算或自动重试。
- 失败场景停止后续场景；超时、取消、失败与进程中断分别有可诊断终态。
- Provider 请求/响应可能包含用户输入相关内容，必须作为本地敏感验收数据处理；不得记录 API Key、Authorization Header 或其他凭据。
- 离线 replay 禁止创建或调用真实 Provider client，且不得产出真实 Provider 兼容性通过结论。
- Runtime 事件和 operation 的业务语义保持不变；本任务仅增强验收编排、关联和报告。
- 实施与测试须保留工作树中与本任务无关的用户数据和改动，不执行破坏性 Git 操作。
- 后端测试从 `backend` 执行，并使用 `backend/.venv/` 中的 Python；不自动安装依赖。
- 开发日志、计划文档按项目规则处理；本计划目录保持 Git 忽略状态，不调整忽略规则。

## 当前实现与缺口

- `runtime_provider_acceptance.py` 已有最多 4 个 Run、16 次请求、每 Run 600 秒的全局约束，并支持 `--resume`。
- 当前场景流程在入口中顺序硬编码；没有统一的每场景预算、总时限及状态迁移定义。
- Provider 请求记录、模型调用 ledger、Runtime 事件、工具 operation 和浏览器状态分散在不同产物中，尚未形成统一关联索引。
- summary 在正常异常清理路径写入，但进程被强制终止时可能留有含义不明的 `running` 状态；早期初始化错误也可能没有完整批次摘要。
- 当前 Provider 记录可用于协议诊断，但没有离线 replay 入口。
- 文档已有“兼容结论限定到当前 `.env` 配置”的约束；需要把配置身份、验收日期及模式明确写入报告，并防止 replay 被误解为真实资格证据。

## 风险与控制

- **Provider 响应含用户输入：** 记录留在本地私有验收目录；文档标明敏感性；禁止提交录制数据、密钥或 Authorization Header。
- **进程强制退出无法执行 finally：** 增量写 summary；下一次恢复识别未终结场景并标记 `interrupted`，不擅自重放或创建额外真实 Run。
- **跨层 ID 不完全可用：** 优先用 ledger `call_id`；缺失时报告明确记录缺口并关联可用的 Run/请求序号，不猜测 operation。
- **超时与失败被误报通过：** 通过条件必须同时符合场景预期终态和事件/operation；“Run 结束”本身不表示通过。
- **总预算与场景预算冲突：** 总预算是硬上限，场景额度只可收紧；耗尽后停止，不自动扩大。
- **离线 replay 被当成兼容性证明：** 独立模式标记、独立 summary 字段和文档说明；replay 不写入真实资格记录。
- **CDP/浏览器故障掩盖原始失败：** 保留服务端/前端/CDP 日志索引；诊断采集失败不覆盖主要错误类别。

## 完成标准

- 每个启动过的场景都有 `passed`、`failed`、`timed_out`、`cancelled` 或可恢复的 `interrupted` 终态记录；批次级失败也有 summary。
- 场景预算、场景时限及全局预算均能在请求发生前阻止越界；失败后不启动后续场景、不自动重试或扩额。
- Provider 记录、Runtime call/event、operation 与 UI 状态可通过稳定关联 ID 或明确的关联缺失诊断串联。
- Replay 能通过录制响应验证解析、状态迁移和 UI 展示，且自动化测试证明无真实 Provider 请求。
- 兼容性结论包含确切配置与日期，并限定在该配置；常规 CI 不触发真实 Provider。
- 本计划所列直接相关离线测试通过，验收文档与实际入口一致。

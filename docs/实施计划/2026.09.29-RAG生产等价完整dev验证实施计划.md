> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 对齐生产服务与答案评测的 RAG 组件构造，在固定 `dev` 题集上显式验证完整生产等价链路，同时保持生产默认开关关闭。

**架构：** 新增共享 `KnowledgeRuntimeConfig` 与 pipeline factory，由 `main.py` 和评测入口共同使用；评测入口通过显式 `production-equivalent` profile 接入 Planner、Hybrid Retrieval、Provider Reranker、CoverageAware Selector、Answerability 和 Answerer。所有 Provider 预算、逐题 Trace 和质量门禁独立记录，失败不静默降级。

**技术栈：** Python >=3.11、Pydantic、httpx、pytest/pytest-asyncio、SQLite、现有 OpenAI-compatible 客户端；不增加第三方依赖。

- 真实 Embedding、Reranker、LLM Provider 调用须另行确认预算、模型、费用、输出路径和恢复方式；本阶段先完成 Fake Provider 验证。

## 目标完整链路

```text
LLM Query Planner -> Embedding -> Hybrid Candidate Retrieval
-> Provider Reranker -> CoverageAwareEvidenceSelector
-> CoverageAnswerabilityJudge -> LLM Answerer -> Citation Validation
```

生产等价 profile 的固定约束：`dev`、`hybrid`、candidate 30、candidate vector threshold 0.2、final 5、conditional planning、provider reranker、coverage-aware、coverage-v1、`allow_insufficient_llm=false`。缺少必要 Provider 配置时必须在请求前失败，不得静默改用 keyword/noop。

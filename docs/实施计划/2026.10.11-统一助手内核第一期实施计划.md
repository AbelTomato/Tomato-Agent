## 1. 范围与完成定义

### 1.1 纳入首期

- `kind=assistant` 默认入口，不要求用户选择 chat / knowledge / writing / code。
- 同一 Run 可调用多种能力，共用累计预算、历史上下文、证据引用和产物。
- 通用澄清、业务确认与恢复核对，动作有版本和幂等键。
- 助手任务支持可空工作区；尚未发生项目操作时通过类型化服务端动作绑定已注册工作区一次，任何项目读取、写入或验证前必须已绑定，绑定后冻结到 Run。
- 模型调用统一计量与持久化：包括策略决策、查询改写、知识回答、提纲和草稿生成；顶层同输入已提交响应可复用，领域以公共工具结果和发布边界复用，未发布生成按安全新尝试处理。
- 工具和领域发布分级恢复：读操作安全重试，写入和产物按前后像/摘要核对，提纲和草稿按领域 ID、版本与幂等键观察，未知副作用保持 waiting。
- 错误分类明确：测试或业务失败可在剩余预算内反馈给助手；权限拒绝、配置不可用和未知副作用分别停止、失败或等待。
- Run 统一传递剩余调用预算、wall-clock 时间、工具超时和取消信号；等待不清零已消耗预算。
- 旧四类请求、历史、代码 v1 快照和 stage v1 快照保持可读取与可操作。
- 原目录读写、测试与 diff 复用已实现能力，不建立另一个代码 Agent 或子 Worker。
- HTTP→Worker→能力→持久化→前端的集成及独立进程故障验证；至少一条真实模型链路验证工具选择、澄清和测试失败后的行为。

### 1.2 不纳入首期

- Docker 自动回退。本期建立能力可用性与验证后端边界，真实回退另立专项。

- 自动批量重写旧记录、迁移业务数据库或调用真实付费 Provider。

### 1.3 最终门禁

- [ ] 普通回答和知识任务无需选择服务；材料不足明确返回，不伪造引用。
- [ ] 一个助手 Run 完成“知识检索→项目读取→修改→测试→diff→解释”，只有满足验证门禁才宣称成功。
- [ ] 一个助手 Run 完成“研究→提纲确认→草稿→保存确认”，确认后能继续原 Run。
- [ ] 所有新路径模型调用经过同一个 Run 级预算；等待、恢复和跨能力切换不重置预算，领域调用不绕过 ledger。
- [ ] 无工作区 Run 在尚无项目操作时可通过服务端动作绑定工作区一次，任何项目操作前已绑定，绑定后不可切换。

- [ ] 已持久化工具操作和领域发布结果不重复生成或保存；未知副作用保持 waiting；领域内部模型调用不承诺 Provider exactly-once。
- [ ] 取消后不发布迟到成功；外部修改冲突、过期动作、重复请求行为明确。
- [ ] 新旧历史不丢失、不重复；旧快照在独立数据库副本读取及恢复回归通过。
- [ ] 前端默认助手模式，能够展示引用、提纲/草稿、测试、diff、澄清和恢复动作。
- [ ] fake 集成、故障测试和浏览器人工核对各有证据；真实 Provider/容器场景单独标识通过、失败或未验收，并记录工具选择、澄清、拒绝和失败后修复行为。

## 3. 契约与文件责任

### 3.1 请求、动作和结果

继续使用 `/api/sessions/{session_id}/tasks`、`/api/tasks/{run_id}`、`/events` 和 `/actions`，不创建并行会话 API。

新请求示例：

```json
{"kind":"assistant","message":"结合资料解释当前项目的缓存实现","client_request_id":"request-1","workspace_id":null,"options":{}}
```

- `TaskKind` 新增 `assistant`，`UnifiedTaskRequest` 对该类型允许 workspace_id 为空或已注册工作区；四类旧请求约束保持原样。
- 助手不接受任意 `options`；本期 `options={}`。检索默认配置来自服务端，引用范围由能力参数表达。
- 新公共动作新增 `provide_input`、`approve_action`、`reject_action`、`bind_workspace`，保留旧动作。`approve_action` 仅确认被冻结的业务动作，不能批准模型任意生成的工具名/命令。工作区绑定 payload 与事务规则见第 3.5 节。
- `provide_input` 的 payload 严格为 `{"message":"非空文本"}`；`approve_action` 的 payload 按待确认类型为 `{}` 或仅含 outline 对象的字典，该对象使用现有提纲 schema 并重新验证引用；`reject_action` 为 `{}`。所有动作核对 action_id、expected_version、client_request_id 和冻结参数摘要。
- `PendingAction` 保存类型、显示内容、允许动作、业务版本、目标能力和冻结参数；其授权范围来自服务端，不能由策略自由扩张。
- `AssistantResult` 保存 answer、citations、artifacts、test_results 和 validation_status。后者取 `not_required`、`passed`、`failed`、`unavailable`，与 Run.status 分开；代码验证不可用不能标 passed。
- 消息/结果事件使用现有 envelope 并带 schema_version；避免把统一与领域历史双写成两条用户轮次。

**任务 1 实际协议（2026-10-11）**：TaskKind/TaskAction 已扩展；助手请求只允许空 options，workspace_id 可空或非空 ID。新动作拒绝空白身份及额外 payload；approve_action 的提纲复用 GeneratedOutline 结构校验，引用成员校验仍由后续执行动作对照服务端快照完成。PendingAction 新增 action_type（默认 legacy）、target_capability、frozen_parameters，旧 JSON 缺少这些字段仍可读取。AssistantResult/CapabilityOutcome 使用 schema_version=1，引用与产物复用既有模型；validation_status 不等同 Run.status。HTTP 创建助手任务暂返回 503/assistant_disabled，且不创建 Run。新增契约测试 55 项，计划指定组合 92 项；直接影响七文件组合 134 项全部通过，无失败或跳过。

### 3.3 快照、模型网关和预算

新增 `AssistantExecutionSnapshot(snapshot_type="assistant", schema_version=1, protocol_version=1)`，不修改旧类型 discriminator：

- 复用消息、HarnessState、逻辑步骤、pending operation、累计调用数、累计执行时间、预算、策略/config 摘要。
- workspace_id 可空；保存 session_id、pending_action、domain_links、evidence_refs、artifact_ids、test_results。
- 领域关联以能力步骤和领域 ID 映射，不再假设一个 domain_run_id 能表示组合任务。
- 解析器保留缺 discriminator 的旧 code v1、显式 code v1 和 stage v1；未知版本明确拒绝。
- 顶层与领域模型调用共享一套 ledger。顶层决策使用持久化逻辑步骤 ID 和输入摘要查找已提交响应；领域内部调用记录父操作 ID、阶段、尝试 ID、输入/config 摘要和实际调用序号，序号用于审计与计量，不作为恢复时匹配旧响应的依据。
- 调用前在 lease 事务中预留预算并记录；每次真实 Provider 请求均计数，失败、响应丢失和重试不退款。顶层已提交且输入/config 一致的响应可复用；领域生成通过公共工具结果或已发布领域结果复用，不要求逐子调用重放。不承诺 Provider exactly-once，也不以调用数冒充精确费用。
- 不沿用只用于评测的 BudgetedRecordingLLMClient 作为业务持久化网关，也不把调用次数伪称精确费用。
- Harness 和领域生成器使用同一个调用网关；避免 Harness 再次扣减网关已计入的同一次调用。模型网关是预算计数唯一事实源。
- 网关提供 Run 局部 `scoped_client(operation_id, phase, attempt_id) -> LLMClient`。领域生成中断且尚未发布时，仅在确认无未知副作用、输入与证据重新校验、剩余预算足够后开始新尝试；已发布提纲/草稿必须复用。不得从 ordinal=0 重建领域分支并盲用旧子响应。细粒度重放后移到第 4.5 节。
- 等待不扣活动执行时间；累计模型/工具调用和活动执行时间不清零。每个 Attempt 持久化开始/检查点时间，异常退出按可核对时间保守结算，不能因重启获得新预算。
- 能力接收 Run 剩余预算、取消信号和当前 lease，不复制一份独立预算。每次工具/领域调用的有效超时为 `min(服务端单次上限, Run 剩余活动执行时间)`；领域内部模型请求也受 Provider 单次超时和父调用剩余时间限制。零预算在调用前拒绝；Run 时间耗尽为 timed_out，单次可恢复超时只有在无未知副作用且 Run 仍有预算时允许调整。
- 取消向模型请求、领域流程和执行后端传播；不能终止的请求丢弃迟到结果。恢复只能由新领取且有效的 lease 继续，旧所有者不得预留预算、提交领域结果或发布成功；无法纳入 fencing 的领域发布接口不得接入新入口。

### 3.5 工作区与失败处理

- `workspace_id=null` 的 Run 可以聊天、检索和澄清；任何项目读取、写入或验证都要求已绑定工作区。新增 `bind_workspace` 动作，payload 严格为 `{"workspace_id":"已注册工作区 ID"}`，仅在待绑定动作且尚无项目操作记录时允许从 null 绑定一次。事务同时核验 Session 归属、服务端授权、工作区 busy、action_id/version 和幂等键，并更新 Run/快照；绑定后冻结，不能由普通消息或模型参数切换。
- 现有 Harness 遇到 `ToolResult.success=False` 会终止。新路径不能只根据布尔值决定 Run 失败，必须由服务端将结构化结果分类后处理；旧路径行为保持兼容。

| 结果分类 | Harness / Run 行为 |
| --- | --- |
| 测试未通过 | 保存测试报告和 validation_status=failed，反馈策略；可在剩余预算与原授权内修复再测，未通过前不可宣称成功 |
| 可恢复业务/参数错误 | 反馈结构化原因，可调整参数或澄清；不通用重试整条流程 |
| 权限拒绝 / 用户拒绝 | 保存拒绝事实，不重复同一请求或换工具绕过；可执行授权内替代方案，无合法方案则解释并停止 |
| 后端/配置不可用 | 标 unavailable，仍可做检索/读取；需要验证的目标不能标通过，可等待环境输入或明确未完成 |
| 执行所有权失效 | 旧 Attempt 立即停止提交；由有效 lease 的恢复流程核对状态 |
| 未知副作用 | 保存事实并 waiting，先观察/核对，不重复执行或换后端 |
| 不可恢复内部错误 | failed；保留结构化原因和已发生修改 |

**任务 1 落地边界**：bind_workspace payload 已严格限制为非空 workspace_id，不接受 path、authorized 等授权事实。CapabilityError.category 枚举为 test_failed、recoverable_error、permission_denied、user_rejected、unavailable、ownership_lost、unknown_side_effect、internal_error；CapabilityOutcome 要求 result 携带结果、waiting 携带待处理动作、failed 携带错误，未知副作用可随 waiting 保存。共享动作 ledger 单测证明同键同请求复用，workspace_id、action_id、expected_version 或 action 改变产生 action_request_conflict；旧任务拒绝新增绑定动作。绑定一次、注册/归属/busy/版本事务核验及 Harness 分类行为尚待任务 3～4，不将本次契约测试视为绑定执行已实现。

## 6. 风险、停止条件和回退

| 风险 | 控制 / 停止条件 |
| --- | --- |
| 自动路由旧 Adapter 被当成统一 Harness | 验收同 Run 混合工具链和模型 ledger；不能只看页面 |
| 领域模型调用漏计或双计 | 网关唯一计数；顶层、领域、重放和失败各有计数测试 |
| ordinal 相同但输入/分支变化 | 首期不做领域子调用重放；后续冻结输入/证据/版本并验证语义检查点 |
| 工作区在澄清中静默切换 | bind_workspace 事务、尚无项目操作、一次绑定及服务端授权/busy 校验 |
| success=False 一律终止或吞掉失败 | 第 3.5 节分类反馈，测试失败可修复但完成门禁不放宽 |
| 领域超时/取消脱离 Run | 剩余预算限制单次超时；传播取消并拒绝旧所有者迟到发布 |
| 写作 running attempt 遗留 | 凭执行所有权与领域发布事实核对；无法证明则等待 |
| 旧快照泛化破坏恢复 | 新 discriminator，旧解析保留；旧故障回归失败立即停止扩大接入 |
| 模型输出误作批准或成功 | 服务端冻结动作和完成校验；未经确认不执行副作用 |
| 历史关联泄漏或重复 | 多 domain_links 校验 Session 归属，原历史保持不变 |
| 测试能力与 Docker 耦合继续扩大 | 公共能力报告可用性；Docker 仅当前执行实现，不写入通用请求必选项 |
| 任务范围膨胀 | 本地 shell、桌面、移动和形象另立专项，不用其弥补首期门禁失败 |

回退方式：关闭 assistant_enabled 后使用原四类入口；不自动降级失败中的助手 Run；新 Run 记录保留可查询，不冒充旧类型。数据库升级先保留独立副本并验证，新字段/表不删除旧数据；真实业务库升级与回滚是另行授权操作。取消保留已执行文件修改，不自动回滚。

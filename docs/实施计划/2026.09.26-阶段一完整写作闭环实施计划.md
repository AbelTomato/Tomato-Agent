# 阶段一完整写作闭环实施计划（计划日期：2026-09-26）

> **状态：任务一至五及任务六机器验收已完成；任务六整体及阶段一待真实模型样例与人工质量验收。**
> **执行方式：** 后续按任务顺序实施。每个代码切片先写并运行失败测试，再实现最小变更并运行目标测试；不自动提交 Git、不调用真实模型、不迁移真实业务数据库。

**目标：** 在现有“显式研究并生成提纲 → 人工确认提纲”能力之上，补齐“显式生成草稿 → 结构与引用校验 → 等待保存确认 → 幂等保存”的真实写作闭环。

**架构：** 继续沿用现有 `WritingTask` 状态机、SQLite 条件版本更新、证据快照和显式保存 API。新增写作专用草稿生成器和草稿执行尝试，复用 `LLMClient`、`Run`、`WritingExecutionRepository` 的边界，但不引入 Worker、队列、通用 Workflow 引擎或自主研究 Loop。

**技术栈：** Python >=3.11、FastAPI、Pydantic v2、aiosqlite/SQLite、现有 `LLMClient`、tiktoken、pytest/pytest-asyncio/httpx、React、TypeScript、Vite；不新增依赖。

**依据：** `docs/实施计划/2026.09.26-Agent系统Harness与Infra演进路线图.md` 阶段一、`docs/guides/技术写作Agent说明.md` 及现有写作执行器、API、前端和测试。

## 全局约束

- 默认在 `仓库根目录` 主工作树实施，保留无关改动。
- 不把 FakeLLM 测试结果描述为真实模型质量验收；真实模型、真实 RAG 快照和付费调用必须单独批准。
- 研究阶段保存的 `CitationSnapshot` 是草稿阶段唯一证据来源；草稿生成不重新检索、不读取其他 Session 聊天历史。
- 模型只能返回受约束的草稿内容或结构化章节与服务端 citation ID；模型不得提供任务状态、文件路径、保存确认、数据库 ID 或工具调用。
- 用户确认和保存必须由显式 HTTP 请求完成；未确认不得生成草稿，未保存确认不得写文件。
- RAG 实验数据库只写入 `backend/data/rag/databases/`，报告只写入 `backend/data/rag/reports/`；业务测试数据库使用 `tmp_path`。
- 不承诺任意外部副作用 exactly-once、进程硬退出自动接管或零重复模型费用。

**接口：**

```python
class DraftConfig(BaseModel):
    max_context_tokens: int = Field(default=12000, gt=0)
    max_response_chars: int = Field(default=50000, gt=0)
    timeout_seconds: float = Field(default=120.0, gt=0)

class DraftGenerator:
    def __init__(self, llm: LLMClient) -> None: ...

    async def generate(
        self,
        topic: str,

        citations: list[CitationSnapshot],
        *,
        config: DraftConfig,

def validate_draft(
    raw: str,
    outline: GeneratedOutline,

    *,
```

**设计要求：**

- 生成上下文只包含主题、用户确认后的结构化提纲和任务已有证据快照。

- 输出统一渲染为 Markdown；渲染路径由服务端决定，模型不得控制文件名或保存路径。
- 对“无证据支撑的章节”“未知 citation”“重复 citation”“额外控制字段”“恶意证据中的指令文本”补测试。

## 任务三：增加草稿执行尝试和原子发布

**文件：**

- 修改：`backend/app/writing/execution_models.py`、`backend/app/writing/execution_repository.py`、`backend/app/writing/executor.py`。
- 必要时新增：`backend/app/writing/draft_execution_repository.py`；只有当现有 `writing_attempts` 的研究阶段唯一约束无法安全扩展时才拆分仓储。

**接口：**

```python
async def execute_draft(
    self, task_id: UUID, *, expected_version: int
) -> WritingTask: ...
```

**状态与持久化：**

- 草稿 attempt 必须带 `task_id`、确认输入版本、`run_id`、模型标识、提示版本、阶段、稳定错误码和时间戳。
- 研究 attempt 与草稿 attempt 的唯一键不能冲突；推荐增加 `kind` 字段并将唯一键改为 `(task_id, kind, input_version)`，同时提供兼容迁移，或使用独立 `writing_draft_attempts` 表。
- 开始执行时原子领取 `drafting` 版本；同版本重复请求在已完成且 `drafting_run_id` 匹配时直接返回，不重复调用模型；`running` 返回 `409`。
- 草稿、任务状态/版本、attempt 完成状态和 Run 完成状态必须在同一 SQLite 事务中提交。
- 提交前任务版本变化时标记 attempt 为 `conflicted`，不得覆盖新任务；失败只允许从新的失败版本重试。
- 取消、Provider 超时、数据库异常必须分别记录 `cancelled`、`deadline_exceeded`、`provider_failed` 或 `storage_unavailable`，不得伪装为成功。

- [ ] 写模型失败、非法输出、超时、取消测试。

**API：**

```http
POST /api/writing-tasks/{task_id}/draft
Content-Type: application/json

{"version":3}
```

请求只接受严格正整数 `version`，拒绝客户端 draft、路径、模型、提示词和预算字段。

```http
GET /api/writing-tasks/{task_id}/draft-attempt
```

返回最近草稿 attempt 的安全字段；无记录返回 `200 + null`，任务不存在返回 `404`。

建议错误映射：`outline_invalid`/`draft_invalid`/`citation_invalid` 返回 `422`；Provider 和模型响应错误返回 `502`；模型未配置、存储不可用、发布失败返回 `503`；截止时间超限返回 `504`；版本/状态冲突返回 `409`。

**验证：** API 集成测试覆盖严格请求体、成功状态委托、错误码、草稿 attempt 查询和未确认不能生成草稿；`test_writing_draft_api.py` 通过 4/4，`WRITING_RETRIEVAL_MODE=keyword pytest tests/test_writing_execution_api.py` 通过 4/4。

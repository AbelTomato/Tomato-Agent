# 代码任务后台执行与可恢复操作闭环实施计划（计划日期：2026-10-10）

> **执行要求：** 按任务顺序实施；每个任务先补充失败测试，再实现最小功能，最后运行该任务的目标测试。实现阶段使用 `executing-plans` 工作流，默认直接在主工作树实施并保留已有改动。每个任务完成后立即更新当日开发日志。

**目标：** 将已完成的 SQLite 持久化执行内核推进为单机单 Worker 下可后台执行、可在服务重启后恢复、可通过状态 API 观察和控制，并由前端提供代码任务的完整操作闭环。

**架构：** 保留现有 `ExecutionRepository`、租约/fencing、快照、恢复分类和 `CodeTaskService` 作为执行事实来源，在应用生命周期中增加单机后台 Worker。HTTP API 负责创建、查询、取消、恢复和触发调度，不再要求请求持续等待整个 Agent 执行；前端通过状态和事件轮询展示任务进度及 artifact/diff。未知文件或 Sandbox 副作用仍进入人工等待，不自动重放。

**技术栈：** Python 3.11+、FastAPI、Pydantic 2、SQLite/aiosqlite、asyncio、pytest、pytest-asyncio、React、TypeScript、Vite；不新增第三方依赖。

**接口约定：**

- `ExecutionWorker(repository, executor_factory, poll_interval_seconds=1.0, max_concurrency=1)`：单 Worker 默认最多一个活动 Run。
- `async start() -> None`：启动后台循环；重复调用必须幂等。
- `async stop() -> None`：停止领取新 Run，等待当前执行任务结束或取消并释放本地任务句柄；重复调用必须幂等。
- `async run_once() -> bool`：尝试领取一个可执行 Run；领取成功返回 `True`，没有可领取 Run 返回 `False`。
- `async recover_on_startup() -> list[RecoveryResult]`：扫描并处理过期执行；安全可重放的 Run 重新进入 queued，未知副作用的 Run 保持 waiting。
- Worker 不直接更新业务状态，所有快照、事件、心跳、终态提交必须经过租约绑定的执行端口。

**2026-10-10 完成记录：** 将创建和 execute API 改为 `202 Accepted` 异步调度契约，HTTP 请求不再执行模型调用；状态查询保留错误/版本/快照摘要及 artifact 结果，事件 API 支持 `after` 增量游标，取消和重复 execute 保持幂等。迁移旧 API/集成测试以通过启用 Worker 的后台完成、取消清理和安全失败映射；补充 `test_code_tasks_async_api.py`。任务 3 目标组 38/38、执行内核回归 72/72 通过，compileall 和 diff check 通过。真实 Provider/Sandbox、前端操作面和生产多 Worker 仍留给后续任务。

**目标：** 创建或触发执行的 HTTP 请求快速返回 Run 状态；执行结果通过查询、事件、取消、恢复和 artifact API 获取，同时保留现有测试可迁移的兼容行为。

**接口约定：**

- `POST /api/code-tasks` 返回 `202` 和 `{run_id, status: "queued", dispatch_status}`，不执行模型调用。
- `POST /api/code-tasks/{run_id}/execute` 只负责确认/触发调度，返回 `202`；重复调用必须幂等。
- `GET /api/code-tasks/{run_id}` 返回状态、版本、错误、最近快照摘要、事件游标和 artifact 引用；不返回敏感输入或完整模型上下文。
- **2026-10-11 契约补齐：** 状态查询和 execute 调度响应不再包含 `events`，也不读取事件历史。`event_cursor` 为查询时数据库已持久化事件的最大 `sequence`（无事件为 `0`）；它与快照中的 `last_event_sequence` 含义不同，不得用它替代客户端已读游标。`snapshot_summary` 无检查点时为 `null`，否则仅包含 `sequence`、`created_at`、`protocol_version`、`schema_version`、`checkpoint_revision`、`last_event_sequence`、`phase`、`logical_index`；旧检查点缺少的快照字段为 `null`。摘要不包含 messages、harness_state、pending_response 或操作输入。前端展示执行阶段和检查点，并在终态已读游标仍落后时继续增量读取。内部执行结果保留事件列表。
- `GET /api/code-tasks/{run_id}/events?after=<sequence>` 支持增量读取，保留旧的无参数读取行为。
- `POST /api/code-tasks/{run_id}/cancel` 在 queued/running/waiting 状态下有明确结果；终态取消返回当前终态而不是重复副作用。
- `POST /api/code-tasks/{run_id}/recover` 必须继续要求 `expected_version`；`continue` 必须显式确认；未知副作用不得被 API 自动改为可重放。
- `recover` 的 `continue` 只提交恢复决策并快速返回 `status`、`recovery_reason`、`run_id` 和 `dispatch_status`；不得在 HTTP 请求内调用模型或执行任务，由 Worker 统一领取 queued Run。
- HTTP execute 入口保留为异步 `202` 契约，不调用同步执行适配；内部执行入口供 Worker 和目标测试使用。

## 验收标准

### 必须通过

- 创建代码任务后 HTTP 请求不承担整个 Agent 执行生命周期，返回 queued/accepted 语义。
- 单机 Worker 能自动领取 queued Run，最多一个活动执行者，旧执行者不能提交状态。
- 应用重启后安全 Run 可重新进入 queued 并执行；未知文件/Sandbox 副作用进入 waiting，不自动重放。
- 取消、恢复、事件增量读取和 artifact 读取具有稳定状态及错误语义。
- 前端能够创建、观察、取消、恢复代码任务，并展示测试报告、diff 和 artifact 引用。
- 现有执行内核、代码任务和原有聊天/知识/写作目标测试不回归。
- README、受控代码任务说明、风险台账和开发日志与实际行为一致。

### 明确不作为本轮完成条件

- 断电级 SQLite 耐久性；
- 多机、多 Worker、分布式调度；
- 任意项目导入和任意 shell；
- 所有 Docker/OpenShell 外部故障组合；
- 生产多租户安全和部署放行；
- 写作任务的持久化后台执行。

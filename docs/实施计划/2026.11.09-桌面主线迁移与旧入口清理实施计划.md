计划日期：2026-11-09。基线：df6d7e4。依据用户确认的《桌面端架构迁移与语言选型建议》执行；Windows x64 为首发目标。

## 目标与不变量

交付唯一桌面入口：React/TypeScript 界面、Rust 本机能力与基础聊天、按需启动且随安装包分发的 Python 复杂助手引擎。保留既有知识、写作、执行与恢复内核。普通聊天不依赖 Python/WSL；复杂任务不依赖开发源码、系统 Python 或 WSL。不为语言统一重写 Agent。

先迁移、验证并重新构建桌面，再集中删除旧 Web 和旧 WSL 桌面。最终文档、目录、构建、测试入口反映实际唯一产品，提交本轮功能与清理 commit。已有用户聊天、凭据与项目文件不作试验数据；安装验收使用独立应用标识和数据目录。原有未跟踪研究文档保留，不混入本轮提交。

- 桌面独占项目、显示会话、消息与设置；引擎独占 Run、Operation、恢复与知识索引。通过版本协议和明确 ID 映射衔接。
- 每次生成有 request_id，流事件按生成归属过滤；终态持久化，重复投递不重复消息。
- 普通聊天历史展示与模型输入分开；最新提问必须入模，输入有明确上限。
- 项目绑定不自动授予读写/执行；项目读取另行显式授权。迁移不把 local 配置冒充已实现宿主 shell。
- API Key 由 Rust 系统凭据管理，私有启动通道传给引擎，不进入日志、命令参数、普通配置或 WebView 后端请求。
- 内部 HTTP 可以保留，但仅限 Rust 管理的 loopback、随机令牌与实例校验。
- 阶段完成必须有验证事实；失败、未验收项如实记录，不用构建通过替代功能验收。

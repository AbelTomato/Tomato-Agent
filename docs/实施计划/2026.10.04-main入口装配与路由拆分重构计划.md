# main 入口装配与路由拆分重构计划（计划日期：2026-10-04）

## 目标

整理 FastAPI 启动入口的职责，将服务装配、应用生命周期和 Session/Knowledge 路由从 `main.py` 中分离；保持现有 HTTP 契约、写作路由和 `uvicorn app.main:app` 启动方式不变。

## 当前问题记录

1. `backend/app/main.py` 同时承担 Repository/Service/LLM/工具构造、Runtime/写作执行器装配、lifespan 与 CORS 配置、路由注册和 Session/Knowledge API 实现。
2. 依赖在模块导入时以全局对象构造，生产装配与测试替换耦合。现有测试直接读取或 monkeypatch `app.main` 中的 `app`、`repo`、`knowledge_service`、`llm_client`、`writing_service` 等。
3. 写作 API 已独立放在 `backend/app/api/writing.py`，Session/Knowledge API 仍写在 `main.py`，路由职责不统一。
4. `main.py` 中的 `create_run`、请求模型、工厂函数也被 `test_main.py` 直接导入或调用，需迁移或短期兼容。

## 范围与约束

- 本计划仅整理应用装配和 FastAPI 路由，不改变 API 路径、请求/响应字段、错误语义、RAG 策略、数据库 schema 或写作状态机。
- 保留 `uvicorn app.main:app --reload` 入口及现有写作 Router。
- 先迁移测试依赖，再移除不再需要的模块级兼容符号；不得一次性删除调用方仍在使用的符号。
- Knowledge 问答服务与写作检索服务目前配置不同，重构中继续分别构造，不合并行为。
- 不新增依赖；通过现有 FastAPI、Pydantic、pytest/httpx 完成实现与验证。

## 文件边界

- 新增 `backend/app/application.py`：`create_app(config: Settings | None = None)`、lifespan、中间件与 Router 注册。
- 新增 `backend/app/dependencies.py`：运行依赖的构造函数/容器，隔离 Repository、Service、Client、ToolRegistry、Runtime 和 WritingExecutor 装配。
- 新增 `backend/app/api/sessions.py`：Session、Agent Run、消息列表 API 及请求模型。
- 新增 `backend/app/api/knowledge.py`：Knowledge capabilities、Knowledge run、文档读取 API 及请求模型。
- 修改 `backend/app/main.py`：保留部署入口和必要的向后兼容导出，不再直接实现业务 API。
- 修改 `backend/tests/test_main.py`、`test_knowledge_api.py` 及写作 API 集成测试：改为从应用工厂/依赖状态进行测试，保留契约覆盖。
- 修改 `README.md` 仅在启动命令或说明确需变化时；预期 `app.main:app` 不变，无需变更。

## 实施步骤

### 1. 固定兼容基线

- 核对 `test_main.py`、Knowledge API 与 Writing API 集成测试访问的 `main` 模块变量、请求模型、路由函数及 `app.state` 属性。
- 为应用工厂契约补测试：指定 Settings 时能创建应用，注册既有路由，并暴露稳定的应用状态依赖。
- 运行 `test_main.py`、`test_knowledge_api.py`、`test_writing_api.py`、`test_writing_execution_api.py`、`test_writing_draft_api.py`、`test_writing_research_integration.py` 建立基线。

### 2. 抽离依赖装配

- 将 Repository、LLM/Embedding client、KnowledgeService、工具注册表、AgentRuntime、WritingService、WritingExecutionRepository、WritingTaskExecutor 的构造集中到 `dependencies.py`。
- 采用具名依赖对象保存运行服务，并将依赖放入 `app.state`；lifespan 只负责初始化仓储和应用运行资源。
- 添加装配测试，覆盖未配置 LLM/Embedding 时的行为和写作/知识服务使用各自配置的约束。

### 3. 拆分 Session/Agent 路由

- 将 Session 创建、普通 Run、Knowledge Run 之外的消息历史读取路由及请求模型迁至 `api/sessions.py`。
- 路由通过 `Request.app.state` 或 FastAPI dependency 读取依赖，不从 `main.py` 模块全局变量读取。
- 保持 UUID 校验、Session 404、Run 事件写入、错误状态和响应 JSON 不变；补充/迁移对应测试。

### 4. 拆分 Knowledge 路由

- 将 capabilities、Knowledge Run 和文档详情路由迁至 `api/knowledge.py`。
- 路由显式读取 KnowledgeRepository、KnowledgeService、LLMClient 和 SessionRepository；保持 history query rewrite、事件记录、引用响应与错误处理一致。
- 更新 Knowledge API 测试，验证可通过工厂或 app state 注入临时仓储及 Fake LLM。

### 5. 建立应用工厂和兼容入口

- `application.py` 实现 `create_app(config: Settings | None = None)`，装配依赖、lifespan、CORS 和 sessions/knowledge/writing routers。
- `main.py` 导出 `app = create_app()`；部署命令保持兼容。
- 将仍被测试调用的类型/函数迁至其新模块，并在迁移完成前从 `main.py` 重导出；之后只移除无调用方的兼容符号。
- 验证 ASGI app 创建、路由注册、lifespan 初始化及 app.state 依赖均符合预期。

### 6. 回归与收尾

- 迁移所有依赖 `main` 全局状态的 API 测试到 app state/dependency 注入，避免测试依靠 import 时副作用。
- 运行上述六个目标测试文件；另执行相关源码和测试的 `compileall`。
- 确认 README 启动方式仍有效、路由 OpenAPI 路径集合未变化，并运行 `git diff --check`。
- 在当日开发日志记录完成内容、问题、解决方式和验证结果。

## 验收标准

1. `main.py` 只负责兼容入口，API handler 与主要装配逻辑已迁出。
2. `uvicorn app.main:app` 的导入契约保持不变。
3. 六个目标 API/集成测试文件通过，Session/Knowledge/Writing 路由契约无回归。
4. 应用依赖可在测试中显式替换，不要求修改模块级全局对象才能隔离服务。
5. 不改变数据库、外部服务调用、模型策略及业务状态迁移。

## 风险与控制

- 现有测试广泛访问模块级对象；分阶段保留兼容导出，并按调用点逐步迁移。
- `httpx.ASGITransport` 测试可能不运行 lifespan；路由测试与 lifespan 测试应分别验证。
- 将对象构造时机从 import 时移至 app factory 可能影响 monkeypatch 时序；通过明确的依赖构造参数/state 消除隐式顺序。
- 当前 CORS 来源、方法和 Header 白名单属于运行行为，应用工厂必须原样保留。
- 若迁移中发现有调用方依赖本计划未列出的 `main` 私有实现，先维持兼容导出，不扩大业务重构范围。

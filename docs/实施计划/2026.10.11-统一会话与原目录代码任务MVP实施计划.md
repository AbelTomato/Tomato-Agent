# 统一会话与原目录代码任务 MVP（计划日期：2026-10-11）

> 执行方式：使用 `executing-plans` 按任务顺序实施，每项完成后记录实际验证结果；任务 1～8 已完成（2026-10-11）。

**目标**：用户在同一会话界面使用普通聊天、RAG、技术写作和代码任务；代码任务选择本机已有 Python 项目原目录，直接修改、受控验证、审阅本轮 diff，并继续下一轮任务。

**架构**：统一 Session、Run 生命周期、事件与人工动作协议，复用既有领域服务和单 Worker。代码任务保留逐操作持久化恢复；聊天、RAG 和写作通过阶段适配器接入外层状态机，不承诺领域内部逐操作恢复。工作区长期注册，Run 固定绑定工作区，变更基线按 Run 保存。

**技术栈**：Python ≥ 3.11、FastAPI、Pydantic、aiosqlite、SQLite、React、TypeScript、Vite、pytest、node:test；代码验证复用 Docker。

**需求依据**：用户已确认统一会话/执行框架、原目录模式，并要求最小 MVP。本文包含首期设计与执行任务，不依赖另一个尚未生成的设计文件。

## 3. 公共契约与状态语义

### 3.1 模型

| 模型 | 首期字段/职责 |
| --- | --- |
| Session | id、metadata、default_workspace_id、created_at、updated_at |
| UnifiedTaskRequest | kind、message、client_request_id、workspace_id、类型化 options |
| RunRecord | 既有字段 + 可空 session_id/workspace_id、结果、阶段、pending_action、request 去重标识 |
| RunEvent | 既有 run_id/sequence/event_type/payload，公共消息和结果事件带 schema_version=1 |
| PendingAction | action_id、reason、allowed_actions、业务版本、展示数据 |
| WorkspaceRecord | workspace_id、mode=managed/original、repo_path、metadata_path、注册时目录身份、pytest 配置摘要 |
| RunFileChange | run_id、path、初始内容/摘要、最近观察摘要、Agent 写后内容/摘要、冲突事实 |

TaskKind 固定为 `chat`、`knowledge`、`writing`、`code`；在统一接口中不要继续增加别名。旧接口中的 `code_task` 由兼容层映射。

Run 的 workspace_id 对无工作区任务为 null，不创建假的空工作区。旧 managed 工作区与快照仍能读取。领域 Run ID 单独保存为关联字段，不能与统一 Run ID 混用。

数据库：task_runs 增加关联字段；现有 workspace_id NOT NULL 约束需通过事务建新表/复制/替换并保留关联表引用，不能只改 Pydantic。迁移测试须同时启用外键并执行 `foreign_key_check`，核对索引与行数。新增字段后所有 INSERT 使用显式列名。

### 3.2 迁移规则

沿用 queued、running、waiting、completed、failed、cancelled、timed_out。公共规则由 `app.runs.state_machine` 提供；Attempt、Operation 状态机继续独立。

- queued → running/cancelled/timed_out/failed。
- running → waiting/completed/failed/cancelled/timed_out。
- waiting → running/completed/failed/cancelled/timed_out。
- 终态不能回到运行态；幂等读取/重复确认可以返回已有终态。
- 等待后重新排队采用显式 resume：waiting → queued，仅在没有有效执行者且确认/恢复条件成立时允许。在公共规则及内核事务中同时实现；禁止适配器绕过 managed-run 写保护。
- 状态、结果和相关事件在同一提交边界保存。迟到生成结果校验版本/租约后才能提交。

写作一个顶层 Run 持续到保存完成；research/draft 的领域 attempt 不变。确认提纲后后台生成草稿；草稿发布后等待保存确认。无证据为失败/业务不足结果，不伪造提纲或引用。聊天/RAG 的领域消息只持久化一次，时间线通过关联读取，不能再复制一次 assistant 消息。

### 3.3 恢复与调度

- 复用 `ExecutionWorker` 的领取、租约、心跳及 fencing，按 kind 分派执行器。
- 代码继续使用 v1 CodeExecutionSnapshot；新非代码快照使用独立的版本化 StageExecutionSnapshot，保存领域 ID、阶段、输入版本、配置摘要和待确认动作。序列化有明确 discriminator，不能将写作状态硬塞进 test_results。
- Worker 通用读取快照采用明确的公共恢复头；需要修改内核中直接访问代码字段的地方并回归旧 v1 快照。
- 非代码 queued 可领取；生成中断明确标记 failed/interrupted，不自动重放模型调用。重新发起生成使用新 Run。
- 写作 waiting 可恢复并确认；领域发布成功而外层事件未提交时，按领域版本/attempt 结果补齐，不重复生成。
- 保存是副作用：沿用固定 idempotency_key，先检查领域保存结果。事实未知进入 waiting/save_outcome_unknown，禁止当作普通生成失败重试。
- 首期一个 Session 最多一个非终态顶层 Run；原目录工作区最多一个非终态代码 Run，包含 waiting。创建时在 SQLite 事务中校验，取消后仍有未知副作用的工作区保持阻塞直到核对，不能只检查 running。

### 3.4 API 与错误

| 方法与路径 | 请求/响应要点 |
| --- | --- |
| GET /api/sessions | limit/offset，返回会话列表和默认工作区 |
| POST /api/sessions | 沿用现有 metadata 创建 |
| POST /api/sessions/{id}/workspace | workspace_id 或 null；只影响新 Run |
| POST /api/sessions/{id}/tasks | UnifiedTaskRequest；202 返回 run_id/status/version |
| GET /api/sessions/{id}/tasks | 分页，服务端创建顺序稳定，读取关联领域历史 |
| GET /api/tasks/{id} | 任务类型、状态、阶段、结果、动作与能力 |
| GET /api/tasks/{id}/events | after 非负游标、limit；返回 next_cursor |
| POST /api/tasks/{id}/actions | action_id、action、expected_version、类型化 payload、client_request_id |
| POST /api/workspaces | path、pytest_paths；服务端选择固定镜像及命令 |
| GET /api/workspaces | 注册工作区与可用状态 |

actions：cancel、confirm_outline、save_draft、inspect_recovery、continue_recovery；按 kind 和 pending_action 限定，恢复继续还需明确 confirmed。outline payload 为既有 outline 结构；保存幂等键由服务端生成并在动作创建时冻结。

knowledge options：retrieval_mode、limit；其他类型拒绝知识字段。code 必须有可用工作区和 pytest 目标。client_request_id 在同一 Session 内唯一；重放相同请求返回原 Run，内容不同返回 409。unknown workspace/Session 返回 404；版本、活动任务、目录变化、配置变化或写入冲突返回稳定的 409 code；无模型/Worker/验证后端返回明确 503，不在请求中偷偷同步执行。

## 5. 风险、停止条件与恢复方式

| 风险 | 控制与停止条件 |
| --- | --- |
| 两套 Run/消息双写重复 | 统一 Run 保存领域关联，历史排除重复；出现重复先修契约，再继续前端 |
| 快照泛化影响已验收代码恢复 | 明确 discriminator、v1 兼容及旧 fencing 回归；不能以放宽恢复换通过 |
| 外部编辑器与 Agent 竞争 | 摘要与原子替换、冲突拒绝；不保证跨应用完全原子性，不自动覆盖 |
| 原目录敏感内容被测试读取 | 根目录配置、文件工具过滤；容器挂载整个项目仍可读取其中敏感文件，首期仅可信项目且不得含运行凭据，此限制明确写入说明 |
| pytest 可运行项目任意代码 | 无网络/凭据、只读挂载、非 root/资源限制；不使用宿主机兜底 |
| 只读挂载不能支持写项目的测试 | 明确不支持，返回限制；不临时放开整目录写权限 |
| 安装依赖导致范围扩大 | 首期镜像预置依赖，不自动安装；依赖不满足停止该项目验证 |
| 外层 Run 与领域提交分裂 | 重启核对领域版本/幂等结果；未知保存保持 waiting |
| 验收项目被当作可删除资源 | 默认保留独立验收目录，不执行用户原目录删除 |

恢复方式：业务改动在主工作树保持可审阅；不自动 git reset。数据库迁移保留迁移前备份，在独立副本验证恢复；实际迁移/回滚需明确操作范围。原目录代码修改通过本轮 diff 审阅，取消不会回滚；MVP 不提供自动撤销。

## 2. 不可跨越的门禁

1. 只在 `dev` 开发和比较策略；不读取、运行或为调参解析 `test` 问题内容。只有冻结策略并通过 `dev` 质量门禁后，才单独申请一次保留集评估；之后若根据 `test` 调参，须标记该集合失去独立性。
2. 实验快照仅放在 `backend/data/rag/databases/`，逐题报告、Trace、人工复核及 provenance 仅放在 `backend/data/rag/reports/YYYY-MM-DD/public-blog/dev/<strategy>/<run-id>/` 等新建目录；不覆盖旧工件，不写 `/tmp` 或业务库。完整内容遵循评测规范的访问权限和留存要求。
3. 真实 Embedding、LLM 或其他外部 Provider 调用，以及任何快照构建写入，执行前必须单独明确目标、请求上限、预算、输入指纹、输出路径、影响和恢复方式并获得批准；本计划不是授权。未知 usage/费用记为未知，不从延迟估算。
4. 执行失败不算空结果或正确拒答；`incomplete` 不输出质量收益结论。BM25、cosine、RRF 与 rerank 分数不得跨类型直接比较。离线空结果只是拒答代理，Judge `supported`、引用白名单合法和 Trace `complete` 均非语义通过。
5. 不因单个 `dev` 失败样例硬编码题目/文档 ID 到业务逻辑；保留原策略默认配置，直到最终门禁与回滚验证通过。所有代码切片先写失败测试，再做最小实现、运行目标回归。

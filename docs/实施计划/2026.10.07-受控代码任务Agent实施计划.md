**目标：** 构建一个能在独立 workspace 中读取代码、修改文件、运行固定测试，并返回合法 diff 与测试报告的受控代码任务 Agent。

**架构：** 在现有 Agent Harness、Runtime、Tool Registry 和 failure-closed Sandbox 契约之上，新增通用 Task Run、Workspace、Artifact 和代码任务编排层。模型只提出结构化工具调用；服务端策略决定能力边界；Sandbox 后端负责实际隔离执行；程序根据 diff、测试和路径校验决定任务是否完成。

**技术栈：** Python 3.11+、FastAPI、Pydantic 2、SQLite/aiosqlite、pytest、pytest-asyncio、现有 Agent Runtime/Harness；不新增第三方依赖。

**规格依据：** 本轮已确认的“受控代码任务 Agent”设计：独立 workspace；首批工具为 `list_files`、`read_file`、`search_files`、`write_file`、`apply_patch`、`run_tests`、`get_diff`、`collect_artifact`；默认禁网；不开放任意 shell；最终结果必须包含合法 diff、测试报告、产物引用和使用量。

## 全局约束

- 默认直接在主工作树 `仓库根目录` 实施，保留已有未提交变更。
- 不新增未在 `backend/pyproject.toml` 声明的依赖。
- 模型不得提交或修改 `CapabilityProfile`、允许路径、网络、凭据和资源限制；这些值由服务端任务策略生成。
- Sandbox 后端不可用、策略校验失败或隔离能力不足时必须 failure-closed，禁止回退到宿主机任意命令执行。
- 代码任务只能访问其 workspace 内的相对路径；拒绝绝对路径、`..` 路径、符号链接逃逸和 workspace 外写入。
- 第一版不提供任意 `shell` 工具；测试执行只能使用服务端登记的测试目标或命令模板。
- 第一版使用单机、单 Worker 的可恢复接口设计；不在本计划内引入分布式队列、多租户鉴权或生产部署。
- RAG 数据库和报告继续使用项目规定的目录；本功能的 Run、Workspace、Artifact 数据不得写入业务 RAG 数据库。
- 实现改变公开行为、接口或配置时，必须同步更新 README、相关说明文档和当日开发日志。

## 验收标准

1. 代码任务拥有独立 Run、workspace 和 artifact 归属，状态、事件和 checkpoint 可查询。
2. Agent 只能使用注册工具；模型无法提交 sandbox policy，无法调用任意 shell。
3. 所有文件操作被限制在 workspace 内，绝对路径、目录逃逸和符号链接逃逸均被拒绝。
4. `run_tests` 只执行服务端登记的测试目标，能区分测试失败、超时、取消、策略拒绝和执行异常。
5. 默认网络和凭据关闭；sandbox backend 不可用时 failure-closed。
6. 任务成功必须同时满足合法 diff、修改范围、测试通过、artifact 可读和 Run 状态一致。
7. 取消、超时、预算耗尽、策略拒绝和失败测试不能被模型文本覆盖为成功。
8. 端到端结果包含 changed files、diff artifact、test report、event trace 和 usage。
9. 现有 Session、Knowledge、Writing 路由及相关测试不发生契约回归。
10. 文档明确区分 fake backend 工程验证与真实隔离后端安全验收。

## 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| workspace 伪隔离导致读写宿主机文件 | canonicalize 后做根目录包含判断；覆盖绝对路径、`..`、符号链接和边界前缀测试。 |
| `run_tests` 演化为任意 shell | 只接受登记目标和结构化参数；拒绝 shell、cwd、env 和 command 字段。 |
| 模型把测试通过当成任务完成 | 程序独立校验 diff、修改范围、测试结果、artifact 和 Run 状态。 |
| Runtime 与 Harness 出现两套预算语义 | 通过适配复用现有循环；先用契约测试锁定行为。 |
| 同步 API 长时间占用请求 | 首期同步闭环，但 Run、事件和取消接口按后台执行方式建模。 |
| fake sandbox 被误认为真实安全 | 文档与路线图单独标记 fake 证据；真实后端另做集成与故障注入报告。 |
| 大量输出或文件拖垮运行 | 对单文件、总 artifact、工具结果和测试输出分别设置上限并显式标记截断。 |
| 中断后 Run 留在 running | 工具前后记录事件和 checkpoint；取消路径执行最终化逻辑。 |
| 破坏 Writing/Knowledge | 新服务和工具集独立注册，运行既有 API/Agent 回归测试。 |

## 三、数据与实验约束

### 3.1 数据集

保留 `backend/evals/blog_questions_smoke.jsonl` 的 5 题 smoke，仅验证链路，不承担效果结论。

正式题集使用已有规范约定路径：

`backend/evals/blog_questions.jsonl`

- 首期目标为人工核验的 30–50 题；数量不足如实报告，不用相似合成题补数。
- 覆盖术语、代码/API、改写、跨文章、无答案和硬负例。
- 按主题/事实组划分 dev/test，不机械按行随机切分；同一事实的改写不得跨集合。
- 已用于阈值校准的 smoke 题不得进入独立 test。
- 无答案表示冻结语料不能支持回答，不代表问题本身没有答案。
- 沿用原文版本与闭区间行范围作为证据，不绑定 chunk_id；增加 group_id 检查分组泄漏。
- 可回答题必须有证据；无答案题必须使用空证据数组；核验文档存在性、版本和行号边界。

### 3.2 实验身份与可比性

记录问题集文件及选中 split 指纹、原始语料指纹、索引指纹、分块/Embedding 配置、策略名、有效配置、实现版本、指标版本、缓存模式、运行环境和时间。未提交代码不能仅用 Git revision 标识，应补充相关源码内容指纹。配置使用白名单，不保存密钥或完整环境变量。

不能要求所有实验索引相同，否则无法比较分块和 Embedding 策略。分为：

1. **固定索引比较：** 只改变检索、阈值或排序策略，索引必须一致。
2. **索引策略比较：** 允许显式声明分块或 Embedding 变化；原始语料、题集和指标口径仍须一致。

未声明的差异标记为 incomparable，禁止自动判定提升。语料/索引指纹采用稳定排序的知识数据内容，不对含会话数据的整库文件直接散列。

### 3.3 隔离与延迟

- 使用经批准准备的独立知识库快照；运行时不得初始化、迁移或写入业务数据库。
- 固定查询向量的本地检索实验，与包含外部 Embedding 请求的真实检索实验分开记录。
- 查询缓存按查询文本和完整模型配置寻址；不跨模型复用。
- 不同缓存、并发、预热或硬件条件下的延迟不得直接混比。
- 模型别名及外部服务可能变化，不能将在线实验描述成严格确定性实验。

## 四、指标及判定口径

| 指标 | 定义 |
|---|---|
| Evidence Recall@1/3/5 | 每题命中证据段比例，再对可回答题取宏平均 |
| MRR@5 | 可回答题首个命中证据结果的排名倒数均值 |
| Hit@5 | 可回答题中至少命中一个证据段的比例 |
| 无答案空结果率 | 无答案题中检索为空的比例，作为拒答代理指标 |
| 可回答题空结果率 | 可回答题中检索为空的比例 |
| 错误召回率 | 无答案题中检索非空的比例 |
| 延迟 | 同等计时条件下的 p50、p95、max 和样本数 |
| 执行错误率 | 超时、协议错误等执行失败占比 |

约束：

- 检索空结果不等于最终答案正确拒答。旧字段 incorrect_answer_count 实际表示无答案题非空检索，不得表述为真实错误作答数。
- 执行失败单独记录，不算空结果或正确拒答；有失败的运行标记 incomplete，禁止输出总体提升结论。
- 分母为零输出 null 和样本数，不输出误导性 0%。
- 保留当前单片段完整覆盖证据段的定义；未来多片段联合覆盖需升级指标版本。分块比较应明确该口径对小片段的影响。
- BM25、余弦和 RRF 分数记录各自 score_type，不直接比较数值大小。
- 总体和类别报告同时展示样本数；小样本结果不宣称统计显著性。

比较输出绝对变化与相对变化；比例绝对变化显示百分点，基线为零时相对变化为 null。

首期质量判定采用保守的描述性规则：所有已声明质量指标不退化且至少一项改善为 improved；全相同为 unchanged；有升有降为 mixed；只有退化为 regressed。浮点差异容差固定为 1e-12。类别变化单列警告，不被总体平均掩盖。实验不兼容为 incomparable，运行缺失/失败为 incomplete。

该判定不是统计显著性结论或自动上线许可。延迟独立展示；未预先声明性能预算时不设硬门禁。后续配对 bootstrap 应按事实组重采样，作为独立扩展，不用 5 题 smoke 宣称显著提升。

主要风险：标注成本、保留集污染、语料/模型漂移、分块与指标的耦合、小样本波动、环境导致的延迟偏差，以及评测链路与业务检索逻辑分叉。分别通过人工核验、分组隔离、快照指纹、指标版本、样本数披露、计时条件记录和复用检索实现控制。

- [ ] 相同输入可复现质量指标，运行工件可追溯。
- [ ] 新旧策略可逐题和按类别对比。
- [ ] 不兼容实验、失败运行和缺失结果不会产生虚假提升结论。
- [ ] 报告能说明提升多少、退化在哪里、代价是什么。
- [ ] smoke、dev、test 与人工答案评估边界清晰。
- [ ] 未执行实验明确标记，不用单测通过数代替效果。
- [ ] 本期不声称最终答案质量提升，不承诺未经测量的收益。

交付分两层：工程测试通过表示 Benchmark 工具可用；正式题集人工核验、真实基线归档和已知风险单独记录后，表示 Benchmark 基线建立完成。Benchmark 基线建立完成不等于 RAG 产品质量验收通过；后者仍需独立的检索、答案语义、引用支撑和拒答质量证据。

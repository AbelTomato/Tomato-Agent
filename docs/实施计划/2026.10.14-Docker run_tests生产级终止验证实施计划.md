> **计划状态**：已批准；任务 1～3 已完成工程阶段验收，任务 4～7 待实施。本文只定义 Docker `run_tests` 的生产级终止验证闭环；OpenShell、通用外部副作用和人工风险接受不在本计划的完成范围内。

**目标：** 为服务端启动的 Docker `run_tests` 执行建立可持久化、可撤销、可查询且 failure-closed 的终止生命周期，使只有真实确认同一执行对象已终止时才能解除该执行的 quarantine。

**架构：** 保留现有 `ExecutionRepository`、operation/Step、lease/fencing 和 settlement projection 作为事实来源。Docker 执行身份在启动前以事务方式落库；正常返回、超时、取消、Worker/宿主机重启和进程崩溃均通过同一身份进入撤销与终止查询流程。只有同一 Docker daemon 上对精确容器对象完成撤销或终止确认，并通过二次查询确认不存在/已停止，才生成结构化 `termination_evidence`；任何未知状态继续保持 quarantine。

**技术栈：** Python >= 3.11、FastAPI、Pydantic v2、SQLite、`asyncio`、Docker CLI、pytest/pytest-asyncio。不得新增 `backend/pyproject.toml` 未声明的运行时依赖。

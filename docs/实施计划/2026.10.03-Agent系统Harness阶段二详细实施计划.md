# Agent 系统 Harness 阶段二详细实施计划（计划日期：2026-10-03）

> **执行提示：** 本计划应使用 `executing-plans` 按任务顺序执行；每个任务先补测试，再实现最小变更，完成直接相关验证后再进入下一任务。

**目标：** 在不重写现有业务状态机和 RAG/写作主链路的前提下，提炼可由研究与写作复用的 Harness 核心，并用固定任务集验证受限自主研究是否比确定性检索产生可接受收益。

**架构：** 保留 `WritingTask`、执行尝试和人工确认等业务状态边界；新增的 Harness 只负责共享的模型调用、预算、上下文、工具策略、停止条件和执行结果。研究路径以可选策略接入受限自主 Loop，写作路径先复用公共上下文/预算/工具契约但继续由 `WritingTaskExecutor` 控制阶段迁移。Sandbox 只通过独立的 `SandboxExecutor` 契约和服务端生成的 `CapabilityProfile` 验证，不迁移 RAG 或写作主流程。

**技术栈：** Python >=3.11、FastAPI、Pydantic v2、SQLite/aiosqlite、现有 `LLMClient`、`tiktoken`、pytest/pytest-asyncio/httpx；不新增依赖，不部署或调用 OpenShell。

**开发环境：** 后端 Python 虚拟环境固定使用 `backend/.venv`；从 `backend` 目录执行测试时使用 `.venv/bin/python -m pytest`，不得依赖系统 Python 或 PATH 中的 `pytest`。

**依据：** `docs/实施计划/2026.09.26-Agent系统Harness与Infra演进路线图.md` 的阶段 2、`docs/guides/技术写作Agent说明.md`、`backend/app/agent/`、`backend/app/tools/`、`backend/app/writing/` 现状及对应测试。

## 全局约束与阶段边界

- 直接在 `仓库根目录` 主工作树实施；保留与本计划无关的既有改动，不执行重置、清理或分支/worktree 操作。
- 阶段 2 不实现 Task/Run/Attempt 租约、后台 Worker、队列、多 Worker、自动恢复、通用 Step 引擎或长期向量 Memory；这些属于阶段 3–5。
- 业务状态机继续由现有 writing service/repository/executor 管理；模型输出不得直接改变任务状态、用户确认、保存路径或权限。
- 不默认启用自主研究；策略必须可配置、可关闭，并保留确定性检索基线。
- 工具权限、预算、超时、输出限制和停止条件由服务端强制；模型不能提交任意策略、扩大白名单或绕过人工确认。
- 恶意证据、错误工具参数、上下文超限和预算耗尽必须失败关闭或停止，不得通过提示词注入改变权限。
- 真实 Provider、真实任务质量验收和 OpenShell 真实集成均需单独批准；本计划的自动测试使用 FakeLLM/FakeRetriever/FakeSandbox 和独立临时数据库。
- RAG 实验快照/数据库只写入 `backend/data/rag/databases/`，报告和逐题工件只写入 `backend/data/rag/reports/`；不得写入业务数据库 `backend/data/agent.db` 或 `backend/data/knowledge.db`。

## 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 抽象层复制现有 Runtime，导致两套预算/工具语义 | 先以契约测试锁定现有行为，Harness 只拥有新公共边界，旧 Runtime 通过兼容适配接入。 |
| 自主 Loop 增加调用但没有质量收益 | 固定模型、任务集和预算做对照；无明确收益则默认关闭，不继续扩展策略复杂度。 |
| 证据或工具结果触发提示词注入 | 所有动态内容按不可信数据传递；权限、白名单和状态迁移由代码验证。 |
| Sandbox 伪隔离或后端不可用时静默落回宿主机 | `CapabilityProfile` 服务端生成；初始化、策略和隔离任一失败均返回拒绝，不执行宿主机任意命令。 |
| 实验污染业务数据或泄露 Provider 信息 | 使用独立实验快照和报告目录；所有错误脱敏，未提供 usage 时记录 unknown。 |
| 阶段 2 越界到执行恢复/Worker | 将 Task/Run/Attempt 所有权、租约、调度和恢复留到阶段 3；本阶段只返回内存执行结果和审计摘要。 |

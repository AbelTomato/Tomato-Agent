## 工程契约与离线验证

当前已完成固定 `python_calculator` fixture 的本地工程闭环。Docker/OpenShell 真实 Adapter 已实现，基础隔离、超时和取消验收各 3/3 通过；单机后台 Worker、异步状态 API 和安全恢复已通过 fake/contract 验证，完整资源/生命周期故障注入及多 Worker 恢复仍待独立验证。

服务端通过 `Settings.code_task_budget` 和 `Settings.code_task_capability_profile(workspace_root)` 生成预算与能力配置。预算字段与 Harness 保持同名；`CODE_TASK_MAX_LOOPS`、`CODE_TASK_MAX_TOOL_CALLS`、`CODE_TASK_MAX_DURATION_SECONDS`、`CODE_TASK_MAX_CONTEXT_TOKENS`、`CODE_TASK_MAX_RESPONSE_CHARS` 控制执行预算；`CODE_TASK_TOOL_TIMEOUT_SECONDS`、`CODE_TASK_MAX_TOOL_RESULT_CHARS`、`CODE_TASK_MAX_FILE_BYTES`、`CODE_TASK_MAX_ARTIFACT_BYTES` 分别声明工具超时、输出、单文件和产物大小限制，默认值与 Sandbox 后端配置见[环境变量模板](../backend/.env.example)。workspace 与 artifact 根目录由 `CODE_TASK_WORKSPACE_ROOT`、`CODE_TASK_ARTIFACT_ROOT` 配置，文件、产物和输出限制由对应服务执行。

网络、凭据及进程能力保持关闭，无任意 shell 工具。代码任务配置允许八个工具名称，其中七个 workspace 工具通过 `create_code_workspace_registry(workspaces, artifacts, runs)` 显式注册，普通 Session 不自动获得这些工具。工具检查服务端 `ToolContext` 的 Run/workspace 归属、profile 工具白名单及允许路径；缺失授权时拒绝执行。既有 Sandbox 后端不可用时仍默认拒绝，契约单测通过不代表真实隔离安全验收通过。

workspace 工具为 `list_files`、`read_file`、`search_files`、`write_file`、`apply_patch`、`get_diff`、`collect_artifact`，只接受 workspace 内相对路径。`search_files` 按字面字符串匹配；`apply_patch` 接受 `{"changes":[{"path":"src/main.py","old_text":"old","new_text":"new"}]}`，原文必须恰好匹配一次，不接受 shell 或自由文本补丁。整批补丁先校验路径、匹配和大小再写入；文件系统错误造成的中途写入失败不提供事务回滚。结果以 `truncated` 标记截断；`get_diff` 同时保存完整 diff 产物并返回引用。文件大小由 WorkspaceService、产物大小由 ArtifactService 执行限制，输出上限由服务端 profile 控制。

Workspace 工具验证命令（在后端目录执行）：`.venv/bin/python -m pytest tests/test_code_workspace_tools.py tests/test_tools.py tests/test_harness_policies.py -q`。

`RunTestsTool` 通过显式注入 `TestTargetRegistry` 和 `SandboxExecutor` 使用，输入仅接受 `{"target":"unit","arguments":["-q"]}`。服务端 `RegisteredTestTarget` 固定 argv 命令模板、workspace 相对工作目录和逐项允许参数；未知目标、未登记参数及客户端 command/shell/cwd/env/profile 均被拒绝。工具不执行宿主机命令，默认 Sandbox 后端不可用时返回 `backend_unavailable`。宿主机进程能力保持关闭；真实测试执行通过显式配置的 Docker/OpenShell 隔离后端进行。

测试报告包含执行状态、退出码、`passed`、输出截断标记和错误码，并保存为 Run 归属的 `test_report` ArtifactRef 与 workspace metadata 引用。Sandbox `completed` 表示执行结束，只有退出码为 0 才标记测试通过；非零或缺失退出码保留为测试未通过。超时、取消、策略拒绝和执行异常返回失败及报告引用。报告保存受 ArtifactService 大小限制，无法保存时不会返回成功。代码任务编排统一返回 usage、tool calls、events、artifacts、test results、diff artifact 和 changed files；普通 Session 不自动获得代码工具。

## HTTP API 与完成判定

代码任务 API 包含 `POST /api/code-tasks`、`POST /api/code-tasks/{run_id}/execute`、`GET /api/code-tasks/{run_id}`、`GET /api/code-tasks/{run_id}/events?after=<sequence>`、`POST /api/code-tasks/{run_id}/cancel` 和 `GET /api/code-tasks/{run_id}/artifacts/{artifact_id}`。创建和 execute 请求均快速返回 `202`；创建后 Run 进入 `queued`，显式 execute 只确认调度，启用的后台 Worker 领取后进入 `running`。创建和查询响应包含 `dispatch_status`（`worker_enabled` 或 `worker_disabled`），执行结果通过状态、事件、取消、恢复和 artifact API 获取；事件接口保留无参数读取并支持增量游标。未配置模型时，后台领取后以 `model_not_configured` 完成失败，不会伪造成功。artifact 读取会校验 Run 归属。任务 API 通过应用 lifespan 初始化独立 workspace/artifact 存储，不改变 Session、Knowledge 和 Writing 路由。

API 验证命令（在后端目录执行）：`.venv/bin/python -m pytest tests/test_code_tasks_async_api.py tests/test_code_tasks_api.py tests/test_code_task_integration.py tests/test_application_lifecycle.py tests/test_main.py -q`；本轮任务 3 目标组 38/38 通过。

API 回归还覆盖固定 `python_calculator` fixture 的受控 patch、`unit` 测试目标、diff/artifact 读取、测试失败、重复执行、未知 Run、非法输入、取消幂等和跨 Run artifact 越权。默认应用未启用 Worker 且未配置模型时仍返回 `503 model_unconfigured`；启用 Worker 后由后台领取并复用已有租约，真实 Sandbox backend 不可用时保持 failure-closed。SQLite 内核已支持显式恢复，并通过 fake 独立进程硬崩溃、竞争领取和 fencing 验证；真实 API/Provider/Sandbox 故障矩阵及生产多 Worker 仍待验收。

普通测试非零或缺失退出码作为可修复反馈返回模型，Run 保持运行；模型可在既有循环、工具调用和时间预算内修复并重新测试，每次重测单独消耗工具调用预算，不在工具内部自动重复同一测试。最终测试仍失败时返回 `tests_failed`，预算耗尽时返回 `budget_exhausted`。路径拒绝、未知测试目标、后端不可用、超时和取消立即终止。成功须由程序校验最新测试通过、diff 与测试时的 workspace 一致、修改范围合法及产物可读，模型文本不能覆盖失败。

## SQLite 持久化与显式恢复

新任务创建为 `queued`，领取后才是 `running`。Attempt 每次领取新建，Run 级 fencing token 单调递增；过期执行者不能续租或提交消息、步骤、checkpoint 和终态。执行表与 Run 共用 SQLite 文件；外部 I/O 不在数据库事务内。

先 `GET /api/code-tasks/{run_id}` 获取当前 `version`，然后调用：

```http
POST /api/code-tasks/{run_id}/recover
Content-Type: application/json

{"expected_version": 3, "action": "inspect"}
```

`3` 是示例，必须替换为最新版本。inspect 只读返回恢复原因和动作；获准后可用同一入口提交 `{\"expected_version\":3,\"action\":\"continue\",\"confirm\":true}`，接口快速返回并通过状态/事件观察后续执行。版本冲突、未过期租约、无确认等返回 409 原因码。API 不接受执行者退出或 Sandbox 清理的事实确认字段，未知副作用保持 waiting，不能靠 `confirm:true` 绕过；内核的文件前后像核对与 Sandbox 显式批准仍需受控人工处置。历史无 v1 快照的 Run 不自动恢复，终态不复活。

模型、工具调用前预留预算，失败/崩溃不退款，恢复沿用计数和策略。in-flight 崩溃按调用时长上限保守扣减，模型当前预留全部剩余执行时间，因此模型调用前硬退出可能耗尽时间预算并停止，不能保证一定续跑成功。已持久模型响应和工具结果不重新调用；仅未提交的只读操作允许重试，可能重复调用。不承诺任意外部副作用 exactly-once、零重复模型费用、跨文件原子写入或机器断电恢复；首版假设单机 UTC 时钟正常，未专项验证 WAL/同步策略与断电耐久性。

## 后台 Worker 契约（任务 1～2）

2026-10-10 新增独立 `ExecutionWorker`，并已接入应用生命周期；设置 `CODE_TASK_WORKER_ENABLED=true` 后启动恢复完成才开始领取，关闭时停止领取并等待当前执行。HTTP 创建/查询通过 `dispatch_status` 暴露 Worker 是否启用；默认关闭以保留显式 execute 兼容路径。`start()`/`stop()` 幂等；stop 阻止新领取并等待当前执行，start 可重新启动；`run_once()` 等待本次执行并返回是否领取，忙碌/无 queued Run 返回 False。仅支持 `max_concurrency=1`。

执行工厂是异步 callable `(run, lease, port)`，不得再次 claim；负责通过租约端口提交业务终态，Worker 不将普通返回值认定为任务完成。异常通过租约端口提交 `worker_executor_failed`，循环继续；失租/心跳错误取消本地执行，不提交过期终态。领取仅选择 queued code_task，并在领取事务内重新核对 queued 状态；现有指定 Run 的 claim 语义保持不变。

`recover_on_startup()` 默认每次扫描最多 100 个过期 Attempt，应用按批次处理至不足一批；调用方可调整 `recovery_scan_limit`。存在候选时必须提供当前 `RecoveryObservation` 工厂（构造参数 `recovery_observation_factory` 或调用参数 `observation_factory`），缺失时在过期处理前拒绝。复用内核分类与应用接口，安全结果回到 queued，未知文件/Sandbox 副作用进入 waiting；不伪造执行者退出、文件核对或 Sandbox 清理事实。后台执行器复用 Worker 已领取的租约，不重复 claim；应用配置校验拒绝非正轮询间隔和非 1 并发。

任务 1～2 目标验证：`test_execution_worker.py` **15/15**，应用生命周期、API、代码执行适配和相关回归共 **72/72**。使用独立 pytest SQLite 和 fake 执行工厂，未调用真实 Provider/Sandbox、未写业务库，不构成真实外部故障矩阵或生产放行验收。

后台未配置模型时持久化 `model_not_configured`；同步 HTTP execute 仍返回 `model_unconfigured`。策略不匹配的启动恢复被拒绝，保留既有 Run 状态并将 Attempt 标记过期，不自动重放。`CODE_TASK_WORKER_POLL_INTERVAL_SECONDS` 默认 1 秒且必须为有限正数，`CODE_TASK_WORKER_MAX_CONCURRENCY` 只能为 1。Worker 启用时不要同时调用同步 execute，以免竞争领取；202 接受语义、异步恢复和前端操作面属于任务 3～4。

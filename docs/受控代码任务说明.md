### 原目录工作区注册（统一会话计划任务 2，2026-10-11）

本地可信单用户可通过 `WORKSPACE_ALLOWED_ROOTS` 授权绝对项目根目录，格式为 JSON 数组；默认 `[]` 拒绝注册，禁止 `/`。例如 `WORKSPACE_ALLOWED_ROOTS=["/home/abeltomato/workspace/projects"]`。应用元数据目录必须与注册项目分离，注册不复制项目、不创建全量内容 baseline，也不向项目写隐藏文件。

## SQLite 持久化与显式恢复

新任务创建为 `queued`，领取后才是 `running`。Attempt 每次领取新建，Run 级 fencing token 单调递增；过期执行者不能续租或提交消息、步骤、checkpoint 和终态。执行表与 Run 共用 SQLite 文件；外部 I/O 不在数据库事务内。

先 `GET /api/code-tasks/{run_id}` 获取当前 `version`，然后调用：

```http
POST /api/code-tasks/{run_id}/recover
Content-Type: application/json

{"expected_version": 3, "action": "inspect"}
```

`3` 是示例，必须替换为最新版本。inspect 只读返回恢复原因和动作；获准后可用同一入口提交 `{\"expected_version\":3,\"action\":\"continue\",\"confirm\":true}`。`continue` 只提交恢复决策，不在 HTTP 请求内调用模型或执行任务；可重放的 Run 快速返回 `status: queued`、`recovery_reason`、`run_id` 和 `dispatch_status`，由后台 Worker 统一领取，调用方继续轮询状态与事件。版本冲突、未过期租约、无确认等返回 409 原因码。API 不接受执行者退出或 Sandbox 清理的事实确认字段，未知副作用保持 waiting，不能靠 `confirm:true` 绕过；内核的文件前后像核对与 Sandbox 显式批准仍需受控人工处置。历史无 v1 快照的 Run 不自动恢复，终态不复活。

模型、工具调用前预留预算，失败/崩溃不退款，恢复沿用计数和策略。in-flight 崩溃按调用时长上限保守扣减，模型当前预留全部剩余执行时间，因此模型调用前硬退出可能耗尽时间预算并停止，不能保证一定续跑成功。已持久模型响应和工具结果不重新调用；仅未提交的只读操作允许重试，可能重复调用。不承诺任意外部副作用 exactly-once、零重复模型费用、跨文件原子写入或机器断电恢复；首版假设单机 UTC 时钟正常，未专项验证 WAL/同步策略与断电耐久性。

## 后台 Worker 契约（任务 1～2）

2026-10-10 新增独立 `ExecutionWorker`，并已接入应用生命周期；设置 `CODE_TASK_WORKER_ENABLED=true` 后启动恢复完成才开始领取，关闭时停止领取并等待当前执行。HTTP 创建/查询通过 `dispatch_status` 暴露 Worker 是否启用；Worker 默认关闭，execute HTTP 入口保留但已统一为任务 3 的异步 `202` 契约，不提供同步执行。`start()`/`stop()` 幂等；stop 阻止新领取并等待当前执行，start 可重新启动；`run_once()` 等待本次执行并返回是否领取，忙碌/无 queued Run 返回 False。仅支持 `max_concurrency=1`。

执行工厂是异步 callable `(run, lease, port)`，不得再次 claim；负责通过租约端口提交业务终态，Worker 不将普通返回值认定为任务完成。异常通过租约端口提交 `worker_executor_failed`，循环继续；失租/心跳错误取消本地执行，不提交过期终态。历史任务 1～2 领取仅选择 queued code_task；统一会话任务 5 已扩展为上述类型，并在领取事务内重新核对 queued 状态；现有指定 Run 的 claim 语义保持不变。

`recover_on_startup()` 默认每次扫描最多 100 个过期 Attempt，应用按批次处理至不足一批；调用方可调整 `recovery_scan_limit`。Worker 启动后通过独立恢复协程按 `CODE_TASK_WORKER_POLL_INTERVAL_SECONDS` 周期继续扫描，每轮分批处理至不足一批；正在执行的长任务不会阻塞恢复扫描，扫描异常记录日志并在下一轮重试。`stop()` 同时停止领取和恢复扫描，等待协程结束。存在候选时必须提供当前 `RecoveryObservation` 工厂（构造参数 `recovery_observation_factory` 或调用参数 `observation_factory`），缺失时在过期处理前拒绝。复用内核分类与应用接口，安全结果回到 queued，未知文件/Sandbox 副作用进入 waiting；不伪造执行者退出、文件核对或 Sandbox 清理事实。租约到期后的扫描不代表立即执行，重新排队的 Run 仍需等待执行槽位。后台执行器复用 Worker 已领取的租约，不重复 claim；应用配置校验拒绝非正轮询间隔和非 1 并发。

任务 1～2 目标验证：`test_execution_worker.py` **15/15**，应用生命周期、API、代码执行适配和相关回归共 **72/72**。使用独立 pytest SQLite 和 fake 执行工厂，未调用真实 Provider/Sandbox、未写业务库，不构成真实外部故障矩阵或生产放行验收。

后台未配置模型时持久化 `model_not_configured`；HTTP execute 不调用模型，成功请求返回 `202`，不再返回旧同步路径的 `model_unconfigured`。策略不匹配的启动恢复被拒绝，保留既有 Run 状态并将 Attempt 标记过期，不自动重放。`CODE_TASK_WORKER_POLL_INTERVAL_SECONDS` 默认 1 秒且必须为有限正数，`CODE_TASK_WORKER_MAX_CONCURRENCY` 只能为 1。任务 3 的 202 接受语义与异步恢复已完成，重复 execute 不会竞争领取；任务 4 前端操作面已实现，剩余交互验收范围见本文开头。

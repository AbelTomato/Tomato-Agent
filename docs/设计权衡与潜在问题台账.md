## RISK-001：批量补丁中途写入失败不回滚

- **类别 / 状态**：设计权衡 / 接受限制。
- **当前设计及原因**：`apply_patch` 先校验整批路径、唯一匹配和文件大小，再逐文件写入；实现不包含跨文件事务或回滚。原始取舍理由未明确记录；当前收益是实现简单、预检失败不会开始写入。
- **触发条件与影响**：前面的文件写入成功，后面的文件因文件系统错误写入失败时，可能留下部分修改；工具返回失败不能证明 workspace 未变化。
- **证据与核实日期**：2026-10-09 静态核对 [CodeWorkspaceTool._execute](/home/abeltomato/workspace/projects/Tomato-Agent/backend/app/tools/code_workspace.py:151) 与[受控代码任务补丁契约](受控代码任务说明.md)。本轮未做文件系统故障注入。
- **现有缓解措施**：整批预检可避免路径、匹配和大小校验失败造成部分写入；workspace 支持读取和 diff 核对，但这些能力不等同于自动回滚。
- **重新评估条件**：需要保证多文件原子修改，或允许任务在写入失败后自动恢复、继续执行。
- **后续行动**：比较临时文件提交、备份恢复或 workspace 快照方案；补充第二个文件写入失败的故障注入测试，明确恢复失败语义。尚未建立独立实施计划。

## RISK-002：检索请求全量读取文档、分块和向量

- **类别 / 状态**：技术债务 / 接受限制。
- **当前设计及原因**：关键词检索读取全部文档和分块；向量与混合检索还读取全部 Embedding，再交给内存 Retriever。原始取舍理由未明确记录；实现便于统一复用内存检索算法。
- **触发条件与影响**：语料或并发增长时，全量读取和内存计算可能增加查询延迟、内存占用与数据库读取开销。当前未在本轮测量规模上限，不能据此宣称已有性能故障。
- **证据与核实日期**：2026-10-09 静态核对 [KnowledgeRepository 搜索方法](/home/abeltomato/workspace/projects/Tomato-Agent/backend/app/knowledge/repository.py:145)；历史判断见 [结构审计计划](/home/abeltomato/workspace/projects/Tomato-Agent/docs/实施计划/2026.10.04-其他模块结构问题审计与后续拆分计划.md:79)。
- **现有缓解措施**：搜索方法提供结果数量限制，但 `limit` 不限制前置全量读取；本条未确认其他缓存或容量门禁，不将其计入缓解措施。
- **重新评估条件**：扩充语料、提高并发，或观测到延迟/内存超过约定目标；目标应在性能验收前明确。
- **后续行动**：先测量读取数量、查询耗时和内存，再比较请求内快照复用、缓存或数据库侧候选检索；保持排序及结果契约。结构审计计划提供后续方向，具体性能切片尚待确定。

## RISK-003：写作运行中 attempt 不自动接管

- **类别 / 状态**：设计权衡 / 接受限制。
- **当前设计及原因**：写作采用用户显式推进、有超时边界的调用；同版本 attempt 已处于 `running` 时拒绝重复执行，不自动接管。首期范围明确排除持久化队列、硬崩溃恢复和分布式执行。
- **触发条件与影响**：进程硬崩溃可能使 attempt 留在运行中；重复请求遭遇冲突，不能依赖刷新或自动重试完成恢复。多 Worker 场景需要额外的所有权和接管语义。
- **证据与核实日期**：2026-10-09 静态核对 [WritingTaskExecutor](/home/abeltomato/workspace/projects/Tomato-Agent/backend/app/writing/executor.py:44) 的 draft/research 分支，与[技术写作执行边界](技术写作Agent说明.md)。本轮未做硬崩溃实验。
- **现有缓解措施**：超时、可捕获取消和失败处理，以及版本/attempt 冲突保护；这些机制不能覆盖进程被直接终止后的接管。
- **重新评估条件**：需要长任务后台执行、服务重启后恢复、自动重试或多 Worker 部署。
- **后续行动**：先定义租约、心跳、过期 attempt 处理与发布幂等，再实现 Worker；补充崩溃和接管竞态测试。方向见 [Harness 与 Infra 演进路线图](/home/abeltomato/workspace/projects/Tomato-Agent/docs/实施计划/2026.09.26-Agent系统Harness与Infra演进路线图.md)，本条不代表恢复实现已完成。

## RISK-004：OpenShell 执行退出码存在传输错误歧义

- **类别 / 状态**：外部依赖限制 / 接受限制。
- **当前设计及原因**：adapter 将 exec 的 CLI 退出码 `0–5` 映射为执行结束并保留退出码，供上层判定测试是否通过。固定 pytest 目标使接口较小，但 CLI 退出码没有单独表达远端测试与传输状态。
- **触发条件与影响**：CLI 退出码 1 可能来自测试失败或部分传输错误；后者可能被上层当成可修复测试反馈，消耗后续模型回合。非零退出码不表示测试通过。
- **证据与核实日期**：2026-10-09 静态核对 [OpenShell exec 结果映射](/home/abeltomato/workspace/projects/Tomato-Agent/backend/app/agent/sandbox_openshell.py:114)；歧义记录见 [当日开发日志](/home/abeltomato/workspace/projects/Tomato-Agent/docs/development-log/2026-10-09.md:35)。本轮未复现传输故障。
- **现有缓解措施**：create/upload 非零退出拒绝继续执行；超时、取消及清理失败有独立状态。exec 阶段的传输/测试退出码歧义仍未消除。
- **重新评估条件**：扩大测试目标、升级 CLI/gateway，或将执行结果用于可靠自动修复与生产判定。
- **后续行动**：核实结构化远端退出状态接口，分离传输状态与测试退出码，并补充传输断开、测试失败和正常成功的对照测试。尚未建立独立实施计划。

## RISK-005：OpenShell 生命周期与资源边界验收不完整

- **类别 / 状态**：验证缺口 / 接受限制。
- **当前设计及原因**：已有 OpenShell adapter、固定 digest 镜像、CPU/内存配置、禁网策略及按所有权标签核对清理。首轮真实验收覆盖部分隔离、超时和 exec 阶段取消；原始未覆盖场景的取舍理由未逐项记录。
- **触发条件与影响**：资源耗尽、进程数量增长、延迟创建、daemon/gateway 故障或本地 subprocess 启动永久阻塞时，资源限制、截止时间及无残留保证仍需验证。gateway 重建后的回连地址风险见 [RISK-006](#risk-006openshell-gateway-回连地址依赖动态容器-ip)。
- **证据与核实日期**：2026-10-09 核对 [真实验收用例](/home/abeltomato/workspace/projects/Tomato-Agent/backend/tests/test_sandbox_openshell_acceptance.py:20)、[adapter 生命周期](/home/abeltomato/workspace/projects/Tomato-Agent/backend/app/agent/sandbox_openshell.py:151) 与 [当日真实验收记录](/home/abeltomato/workspace/projects/Tomato-Agent/docs/development-log/2026-10-09.md:43)。日志记载真实验收 3/3 通过，本轮未重跑；取消信号在进入 exec 调用时设置，未证明 pytest 已开始运行。
- **现有缓解措施**：固定命令与镜像、CPU/内存配置、统一执行期限、所有权标签及清理结果检查；清理失败不能返回成功。这些控制不替代资源耗尽、PID 限制和生命周期故障验收。
- **重新评估条件**：生产放行、并发运行、扩大隔离任务范围或升级 CLI/gateway/镜像。
- **后续行动**：分别补充 pytest 运行中取消、启动/创建阶段取消竞态、延迟创建、资源耗尽、PID 限制和 gateway 失联验收，检查任务状态与残留资源；明确永久阻塞的处理边界。后续需独立验收计划，不以现有 3/3 作为完整生产安全结论。

## RISK-006：OpenShell Gateway 回连地址依赖动态容器 IP

- **类别 / 状态**：技术债务、外部依赖限制 / 接受限制。
- **当前设计及原因**：本地 Docker gateway 的 `grpc_endpoint` 写死为当前 gateway 容器内部地址 `http://172.17.0.3:18080`，供 sandbox supervisor 回连获取策略和执行配置。首次配置中 supervisor 无法通过原回连地址连接 gateway，改用当前容器内部 IP 后真实验收通过；稳定地址方案尚未实施。
- **触发条件与影响**：重建 gateway 容器、重建 Docker 网络或重新分配 IP 后，配置地址可能失效。CLI 通过宿主机发布端口连接，`openshell status` 和健康检查仍可能正常，但 supervisor 无法回连，导致 sandbox provisioning 失败。普通停止、启动也应核对地址，不保证 IP 永远不变。
- **证据与核实日期**：2026-10-09 核对 [本地 gateway 配置](/home/abeltomato/.local/state/openshell/tomato-local/gateway.toml:27) 中的固定 IP，以及 [当日真实验收记录](/home/abeltomato/workspace/projects/Tomato-Agent/docs/development-log/2026-10-09.md:43)。曾复现原回连地址连接失败，改用内部 IP 后真实验收 3/3 通过；尚未执行 gateway 重建导致地址变化的故障实验。本地配置链接依赖当前机器环境。
- **现有缓解措施**：重建或网络变化后，通过 `docker inspect` 核对 gateway 内部 IP，更新 `grpc_endpoint` 并重启 gateway；随后检查 sandbox 创建和清理。仅检查 CLI 状态或健康接口不足以验证 supervisor 回连。
- **重新评估条件**：需要长期运行、自动部署、容器自动重建、环境迁移或生产放行。
- **后续行动**：比较专用 Docker 网络与固定 IP、可被 supervisor 解析的稳定地址或部署时自动更新配置；补充 gateway 重建后的创建、执行和清理验收。尚未建立独立实施计划。

# 环境配置说明

应用使用两份本地文件：`backend/.env` 保存 Provider 凭据和连接，`backend/config.local.toml` 保存非敏感运行配置。两者都不提交。权威模板为 `backend/.env.example` 与 `backend/config.example.toml`；根目录旧模板仅提供迁移指引。

## 首次配置

在后端目录、文件尚不存在时执行：

```bash
cp .env.example .env
cp config.example.toml config.local.toml
```

已有文件不要覆盖。填写 LLM 凭据、地址和模型；示例 TOML 显式开启单 Worker，普通聊天/RAG/写作也依赖它。没有 TOML 时保持代码默认：Worker 关闭、关键词检索可用、原目录注册关闭。Embedding 为空时不能使用向量/混合检索；写作默认 hybrid；缺少 Embedding 或索引模型/维度不兼容时，按既有规则回退 keyword 并记录原因。Provider 网络、认证和超时错误不会回退；也可显式设置 `[writing].retrieval_mode="keyword"`。

## Provider 环境变量

| 功能 | 项目 | 必要条件 |
| --- | --- | --- |
| LLM | `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` | 四类统一任务均需有效 LLM 配置 |
| Embedding | `EMBEDDING_API_KEY`、`EMBEDDING_BASE_URL`、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSIONS` | 向量/混合检索选填，维度与既有索引必须一致 |
| Reranker | `KNOWLEDGE_RERANK_API_KEY`、`KNOWLEDGE_RERANK_BASE_URL`、`KNOWLEDGE_RERANK_MODEL` | 启用 Provider 重排时填写 |

各 Provider 凭据独立，不隐式复用。TOML 不接受 Provider 凭据、地址或模型字段。`RUN_ORIGINAL_WORKSPACE_ACCEPTANCE`、`SANDBOX_IMAGE` 等是验收进程变量，不属于应用配置。

## TOML 项目与旧变量映射

完整可用项、默认值和注释见 `backend/config.example.toml`。除下列例外，变量名称为对应字段的大写形式。

| TOML 分组 | 字段与旧 Settings/环境变量对应规则 |
| --- | --- |
| worker | `enabled` → `TASK_WORKER_ENABLED`；`poll_interval_seconds` → `CODE_TASK_WORKER_POLL_INTERVAL_SECONDS` |
| storage | 字段原名：database_path、docs_root、draft_directory、code_task_workspace_root、code_task_artifact_root |
| providers | llm_timeout_seconds、embedding_timeout_seconds 原名 |
| runtime | max_loops、max_tool_calls、max_duration_seconds、tool_timeout_seconds 加 `runtime_` 前缀；max_doc_bytes、max_tool_result_chars 原名 |
| knowledge | 字段加 `knowledge_` 前缀 |
| knowledge.query_planning | 字段加 `knowledge_query_planning_` 前缀 |
| knowledge.answerability | 字段加 `knowledge_answerability_` 前缀 |
| knowledge.rerank | 字段加 `knowledge_rerank_` 前缀 |
| writing | 字段加 `writing_` 前缀 |
| code | 字段加 `code_task_` 前缀；workspace_allowed_roots 使用原名 |

固定单并发、禁网与禁止运行凭据仍由代码校验，不提供 TOML 覆盖项。未知分组/字段、非法语法会阻止配置加载；错误文本不展示配置值。TOML 字段类型和既有 Settings 业务约束继续校验，不改变已接受的预算或 RAG 门禁。

## 优先级与路径

优先级从高到低：显式 `Settings(...)` 参数、进程环境变量、`.env`、TOML、代码默认值。旧环境变量仍可覆盖所有对应配置；同一来源中 `TASK_WORKER_ENABLED` 优先于旧 `CODE_TASK_WORKER_ENABLED`，不同来源先按来源优先级处理。

默认 `.env` 和 TOML 固定从 backend 目录读取，不随启动工作目录漂移。数据库、文档、草稿、工作区元数据及 Artifact 的相对路径统一以 backend 目录解析；项目允许根目录仍必须是绝对路径。显式构造的绝对路径保持不变。

可用 `CONFIG_FILE=/absolute/path/config.toml` 指定另一份 TOML（显式不存在时报错），`CONFIG_FILE=` 空值禁用 TOML。默认 TOML 缺失允许使用代码默认值。Python 调用可以使用 `Settings(config_file=path)` 或 `Settings(config_file=None)`；`Settings(_env_file=None)` 禁用默认 dotenv 和默认 TOML，但显式参数/环境 `CONFIG_FILE` 仍生效。测试 conftest 在导入 Settings 前设置空 `CONFIG_FILE`，独立配置测试显式指定临时文件。

## 旧配置迁移

1. 保留现有 `.env`，先确认旧配置可正常启动。
2. 新建 config.local.toml，将预算、超时、路径、检索策略和 Sandbox 项逐项按映射迁入；不要迁移密钥。
3. 从旧 `.env` 移走已迁入项后，TOML 才会生效；特别注意旧 `CODE_TASK_WORKER_ENABLED=false` 仍会覆盖 TOML 的 enabled=true。
4. 保留 `.env` 中的 Provider 项。旧根目录 `.env` 不自动搬运；默认读取的是 backend/.env。
5. 重启后端，核对所需功能。代码任务还需 digest 固定 Docker 镜像、允许的可信 Python 项目及预置依赖；开启 Worker 不代表 Sandbox 已可用。

本次代码改动不自动读取并迁移现有本地文件、不创建实际 TOML、不修改业务数据库。上线前可保留原配置备份；恢复时撤回对应 TOML 项并使用旧环境配置。现有 MAX_DOC_BYTES 本次已接入 ReadDocs，调整后会实际限制文档大小。
